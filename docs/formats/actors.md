# Actors: Borg7 (roadmap 1B)

An actor is a Borg7: a scene with a state machine of animations. `Borg7Actor` (`AidynRenewed.Rom.Graphics`) reads it.

- **Borg7 (203 actors)** is a 0xC-byte header (the root transform, the state count and the initial state), then 0xC-byte states (a Borg6, a u16 of flags, and the count and offset of the branches), then 4-byte branches (request, chance, flags, target state). Some files are padded to 8 bytes with leftover text. Every actor's root transform is 2 and every actor starts in state 0. All of an actor's animations animate one scene.
- **Requests.** Each frame, the game asks each actor for an animation by number. The requests' names include 0 idle, 2 walk, 3 run, 7 hit, 9 dying and 25 sneak. The port adds 26, a full run, which no original actor has a branch for ([movement](../systems/movement.md#the-full-run)). The branches use 0–22, 25 and 255, which means any request. Dying's states go back to idle like any other's; it's the body that holds a death's last frame ([scripts](../systems/scripts.md#actors)). A state's flag 0x1 marks the initial state, in all but two actors (7613 and 7620). The game doesn't read it, and uses bit 0x2 of the same field at run time.
- **Branching** (`ActorStateMachine.Tick`, `0x80096570`). When the scene clock reaches the animation's length, the game rolls 0–99. It walks the branches in order, and for each whose request is the current one or any, it subtracts the chance. It takes the first branch at which the roll drops below 1, so a chance of 10 after the roll is 11 in 100. With no branch taken, the animation restarts. When the request changes, branches with flag 0x1 that match it are rolled for at once, and the animation doesn't advance that tick. A state takes only a request it has a branch for, by the request's number exactly (`ActorStateMachine.SetRequest`, `0x80096530`; 255 doesn't count); for any other the actor's request is its default, 0, which `ActorStateMachine.Tick` (`0x80096570`) puts back after every tick. So a request still asked for in the state it led to counts as none, a change, and the tick after the state is entered doesn't advance. The port's `ActorStateMachine.Taken` is the request a state takes.
- **The rolls** are `Range(0, 99)` (`Rng.RangeOn`, `0x80093384`, the game's generator on a stream it's given) on one of two streams of the actor animations' own, each shared by every actor: bodies' (`ActorStateMachine.Tick`, from `Bodies.Process` once a body a frame) roll on the word at `0x800e69c0`, and map actors' and the pause menu's scroll's (`ActorStateMachine.Advance`, `0x800967a4`, which loops a frame's ticks) on `0x800e69c4`. Both are in `.bss`, start at 0 and are never seeded or saved, so a session's first roll is (100 × `0x3C6EF35F`) >> 32 = 23. The rolls are cosmetic; nothing in the rules reads them. Where the port's streams differ, `ActorStateMachine`'s remarks say why.
- **Brenna's actor (10723)** is a typical one. Idle (state 0) repeats 90% of the time and fidgets 10%. Walk or sneak starts a walk (1), which alternates two steps (2 and 3) and ends in a stop (4 or 5) when walking isn't requested. Run goes to state 6. Requests 5, 6, 12, 13 and 15 interrupt from 18 of her 25 states; the rest, including hit (7) and dying (9), interrupt only from idle and a few others.
- **Root motion.** The game draws the actor with transform 2's position zeroed, and moves the actor by how far that position moved each tick. It skips the tick a branch is taken or an animation restarts, and the two ticks after; and a body moves only while its request, or the request its state was entered under, isn't idle ([movement](../systems/movement.md)), so a stop's root returning to rest moves nothing. The walk steps are cut from one continuous walk, and skipping those ticks hides the jump back between steps. Brenna's walk comes to about 1.9 scene units a second.
- **In the port** the core's `ActorMotion` (`AidynRenewed.Core.Actors`) plays an actor headlessly, timed and moved by what `ActorClips` (`AidynRenewed.Plugins.Assets`) reads from its scene's glTF: each animation's `length` extra and the root's per-tick samples. So a mod that replaces the scene's glTF replaces its timing and motion with it. An animation the scene lacks lasts a tick, and one that doesn't drive the root moves nothing. The views' `ActorAnimator` poses the scene, with the channels Godot's loader drops posed at rest ([animation](animation.md)).
- **Entities' actors** (`EntityModels`, from `gEntityExtras` and `CodeTable.DialogEntityModels`). Each entry is keyed by the record's position in the code's entity or dialogue entity list, plus 1. Both lists are in the same order as the DB tables. Keying by the record's ID instead would give Alaron Brenna's actor. Every entity and 32 of the 37 dialogue entities have an actor, a portrait, a height and a scale. Entities also have a collision radius and the share of an attack's animation at which its blow lands, which combat reads ([combat](../systems/combat.md#an-attack)). The import gives each entity and dialogue entity its `body`: actor, radius, scale and height. Dialogue entities' radius is 0.55, which the code gives them all, and the five without an entry get the bat (`0x2D4A`) at scale and height 1, as the code does (`EntityDB::GetBorg7`). The other actors belong to scenery, spell effects, the pause menu and the like. The tables and the dialogue entity list are identical in all three ROMs.

The editor shows an actor's states and branches and drives them ([editor](../systems/editor.md)).
