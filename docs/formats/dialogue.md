# Dialogue and cut-scene scripts: Borg13 (roadmap 1E)

`aidyn-enhanced dialogue <rom> [<index>...]` writes each Borg13 as text to `out/<version>/dialogue/`, with speakers named from the DB.

- **Borg13 (892 scripts)** is a 0x18-byte header, then 0x38-byte nodes, then 8-byte actor entries, then plain ASCII text padded to 8 bytes. The text isn't encrypted, unlike the DB strings. It keeps `\n` and `\xHH` escapes, and a run of 20 `#` stands for the player's name. Many scripts carry leftover strings that no node uses, and some end with a blank node that nothing links to.
- **Header:** `ID` is the script's number in the original tools (1004–13147), not its archive index. `flag` is set when a cut-scene, backdrop or help script finishes, but not after a conversation or sign. The start function field is the presentation: 596 conversations, 211 cut-scenes, 78 backdrops (text over a picture, such as a book), 6 signposts and the help menu. `libraryType` picks the backdrop's picture and is 14 everywhere else. Op 19 duplicates it in each backdrop's first node, and the game never reads op 19.
- **Nodes** have four ops (a u16 operand, a command byte, then six zero bytes), a text offset and length, a `[a, b]` range, a first link, seven more links, the node's own index and a flags byte. Links end at the first 0xFF. The flags byte gives the kind:
  - **0x1, line**: shows its text, then follows its one link. With no link it goes back to the last menu or case.
  - **0x2, if**: evaluates a condition (party member, flag or item) and follows the first link if it's exactly 1, else the second.
  - **0x4, case**: evaluates a value (skill, party size or gold) and considers the links whose `[a, b]` holds it. 65000 means no upper bound. One match is followed, and several are offered as a menu.
  - **Otherwise, menu**: offers its links as choices. Choices already taken are hidden, except in backdrops and the help menu.
  - 0x40 is on most menu choices and is never read. 0x80 is the run-time "visited" bit.
- **Ops run in three passes:** every setup op (speaker, cameras, actors, enemies) when the node is reached, the first condition op when branching, and **only the first effect op** when a line is left, or at once for menus and cases. The data agrees: only 4 nodes have a second effect. One of them, node 88 of script 1019, is a `SetFlag` that never runs.
- **Command 53** comes once near the start of every cut-scene, on an empty line, and does nothing in 1.0 but take its node's effect slot (the effect check's jump table, `ScriptRunner.CommandCheckJumpTable` at `0x800D5B08`, and `DialogCallbackC`'s at `0x800D1DE8`).
- **Quirks:** script 1294 has 0xCCCC, the tools' fill value, as an actor and a speaker. Ops 1 and 2 are never read by the game; op 2 often names the node a line links to, like a note from the tools. Node 24 of script 1040 has lost both its link and its op 2, and Trahern's conversation (936) loops on flags nothing sets: see [scripts](../systems/scripts.md).
- **Imported as `records/dialogue.json`:** one `aidyn:dialogue/0xHHHH` record per Borg13, keyed by archive index. The importer does at import what the game does at run time. Text loses its `V0173` line number, keeps every other space, turns a run of 20 `#` into `{player}` and decodes `\n` and `\xHH`; any other `#` or backslash stops the import. Ops 1, 2, 19, 55 and 59 are dropped, since the game never reads them. An operand that names something becomes a record ID: entities, items, spells and gear by their whole u16 (`aidyn:entity/0x023F`), flags, and the script a random line shows. An ID with no record, such as 0xCCCC, keeps its number, and an unset actor is left out. Ops that ignore their operand have none. A node that a Case links to keeps its `[a, b]` range as `selects` (no upper bound for 65000), and no other node has one. Cut-scenes, backdrops and the help menu carry their done flag, and backdrops and the help menu their picture. The record also holds the flag that winning the script's battle sets, whether it's a camp scene (both from tables in the code segment), and `blankNodes`, the trailing blank node the parser drops. Actors can be dialogue entities as well as entities, such as signs and animals.
