# Textures and UI images: Borg1 and Borg8 (roadmap 1A)

`Borg1Texture` and `Borg8Image` (`AidynRenewed.Rom.Graphics`) read them. `aidyn-renewed textures <rom>` writes every Borg1 and Borg8 as PNG, with an `index.csv` of formats, sizes and flags.

- **Borg1 (2,183 textures)** is a 0x18-byte header, then every mip level back to back, then an RGBA16 palette for CI8 (256 entries) and CI4 (16). There are `lods + 1` levels. Each level halves both sides, and each row is padded to at least 8 bytes. No texture has its own display list, and every bitmap starts at 0x18.
- **Borg1 bitmaps are stored in TMEM order.** The game uploads each one with a single `LoadBlock`, so odd rows have each pair of 32-bit words swapped (64-bit words for RGBA32). Undoing the swap makes the first mip level match a downsample of the base level.
- **Borg1 formats:** mostly CI8, then RGBA16, CI4, IA8, IA16, RGBA32, I4, I8 and IA4. The largest is 64×64, apart from one 32×128. Most are 32×32.
- **Borg1 flags:** 0x20 is on exactly the textures with transparent texels. The game's render modes blend IA16, IA8 and RGBA32 textures with it and cut out the rest, by coverage rather than an alpha compare (`Scene.SetRenderMode`, `0x80097618`; see [rendering](../systems/rendering.md#the-n64-material)). A draw whose prim alpha is under 255 blends whatever its texture. 0x200 scrolls, and every scrolling texture also has 0x100, which gives it a second, writable bitmap.
- **Scrolling** (`Scene.LoadTextureOp`, `0x800938b0`; `moveBitmap16` and `moveBitmap32`). Each time a scene's instructions load the texture, the game copies the base level from one bitmap to the other, shifted toward +S and wrapping, and draws the copy. The header's scroll byte (offset 7) says by how much, and the game counts in it. With a low nibble of 0, each load shifts by the high nibble (0x10, 0x20, 0x30 and 0x80 occur). Otherwise the high nibble counts loads up to the low nibble, and the load that finds them equal shifts by that many texels and clears the count. So 0x02 shifts 2 texels every third load, and 0x0E 14 every fifteenth. Odd rows keep their TMEM order. Every scrolling texture is RGBA16, IA16 or RGBA32, with no mip levels, and 32 or 64 wide; the other formats would scroll wrongly, since `moveBitmap32` shifts 32-bit words. Each copy of a scene has its own copy of each scrolling texture: `BorgAnimLoadScene` sets `borgFlag`, and `InitBorgTexture` takes a texture with flag 0x100 out of the Borg cache as it's loaded, so the next scene to load it gets a fresh copy. So a copy moves each time its scene is drawn and stays put while it isn't. [Rendering](../systems/rendering.md#scrolling-textures) has how the port steps them.
- **Some textures are upside down,** the digit glyphs among them. T = 0 is the first row, and the models' texture coordinates are exported as they are, so any flip is the model's own.
- **Borg8 (560 UI images)** is a 0x10-byte header, then the palette (CI only) and a linear bitmap, at offsets from the start of the data. The game draws them with `LoadTile`, so there's no TMEM swap. Formats: mostly IA8 and CI8, a few RGBA32, one RGBA16 and one I4. The largest are the 320×240 menu backdrops.
