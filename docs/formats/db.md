# DB tables (roadmap 0.4)

The fixed databases at the end of the ROM: entities, items, spells, shops, camp encounters and the string tables (`AidynEnhanced.Rom.Db`, `AidynEnhanced.Rom.Text`). What each string table holds, and how the base plugin carries them, is in [text](text.md).

- **Layout.** `RomVersions` places every table of the DB block in all three ROMs; [rom](rom.md#where-each-version-has-its-tables) has the moves. ShopDB starts at 1.0 `0x1FD31B0`. The debug ROM's credits are shorter than 1.0's: three names are missing and one date differs.
- **All records are identical in all three ROMs.** Only the text tables noted in [rom.md](rom.md) differ.
- **String decryption.** The decryption shifts the second seed right by 8, and the key setup mixes all 16 bytes. Every string in every table decrypts to printable ASCII. The only markup is `\n` and `\xHH`, where `\x83` and `\x84` are controller button glyphs. The readers keep both as written.
- **Grouped tables.** EntityDB, WeaponDB, ArmorDB, SpellDB and ItemDB split their records into groups. Each group matches a field: entity category, weapon class, armor slot, spell school, and the item ID's type. EntityDB has 7 categories, and category 4 is empty.
- **Shops.** The game stocks a priced slot only when its third byte is nonzero, and it always stocks one item. The first byte is never read. The three trailing slots are always stocked at base price.
- **Camp encounters** are 27 terrains of ten 8-byte slots, at `terrain × 80 + level tier × 8` (`0x80009728` in 1.0): two groups of a big-endian entity ID, unlike the DB tables, and a minimum and maximum. The code reads only slots 0–4, the five level tiers (an average party level of 5 or less, then 6–10, 11–15, 16–20 and over 20); slots 5–9 look like a second set of tiers it never reads. Terrain 27, which six Overworld chunks have and where camping is allowed, has no row: an ambush there would read past the table ([camping](../systems/camping.md)).
- **Odd values the game tolerates.** A few entities have an "is heavy" byte other than 0 or 1 (Alaron's is 220). The game only tests it for nonzero.
- **Entities' fields** (see [characters](../systems/characters.md) for what the base plugin makes of them):
  - **Categories** are 0 plain NPCs and trainers, 1 humanoids, 2 named characters, 3 recruits, 5 Chaos troops and bosses, and 6 animals; 4 is empty. The code tests 5 for Chaos (Charming fails on it).
  - **A skill of 255** can never be learnt. Values above 10 occur (13 and 15), which read as 10.
  - **Attributes** can be above their caps: some enemies have 120 Stamina, which reads as 90 but counts in full once modified.
  - **Resistances** are an element and a damage multiplier in quarters: 0 is immune, 4 normal and 8 double. 99 entities have (None, 4), which combat ignores.
  - **The reward byte** is × 50 on load, and × 1.5 again when awarded.
  - **Spell slots** with no spell still hold a level, usually 10.
- **Spells' training cost** is their last byte × 50 (`TempSpell::Init`).
- **A spell's `unk1E` byte** is a set of bits (copied to the RAM spell at `+0x20`). `0x01` makes it Lunar and `0x02` Solar: they feed the resist roll's aspect factor (`Combatant.ResistRoll`, `0x80064298`) and which of the target's Solar and Lunar resistances meet it (`SpellResistanceApplies`, `0x80061C5C`), and a spell with neither is aspectless. `0x10` is a placed area: the caster chooses a point, the range is about it, and the spell is resisted though it isn't an Enemy spell (`CanCast`, `BeginSpellTargeting`, `IsResistable` at `0x800641B8`); Fireball, Teleportation and the four dispels have it. `0x20`, `0x40` and `0x80` are never read in combat's code (they split the spells in a way that matches nothing: `0x20` marks the buffs and the Field spells, `0x40` every spell castable in combat but Poison, `0x80` only Poison). The importer writes the first three as `aspect` and `placed`.
- **The "heavy" special** (Earth Smite, Crushing Death, Frozen Doom, Web of Starlight, Poison) needs the target's "is heavy" byte to be **set** (`Spell.TargetRequirement`, `0x800712C0`: "The target is too large!" when it's clear). That byte is set for the party, the rats and ordinary humanoids and clear for the 32 big creatures (the Ogre, Troll, Bear, Minotaur, the golems, the elementals, the Gryphon, the Manticore and so on), so "heavy" is a misnomer: the spell takes only targets small enough. `heavy` on an entity record means this, human-sized or smaller.
- **Weapons', armor's and gear's last 14 bytes** are what wearing them does (see [items](../systems/items.md)):
  - **The spell bytes.** The first byte after the spell's ID is its charges for all three. The second is its level on armor and gear; a weapon's level is the byte at `0x1D`, and its second byte is unread (`InitWeapon`, `InitArmor`, `ItemInstance::InitGear`).
  - **The stat byte** is 0–5 or `0xFF` for none; the code tests for `0xFF`, not nonzero. Stamina (5) isn't raised: it's a spell battery.
  - **The skill byte** indexes the character's 24 bytes of skills, weapon skills and the shield, but the data names skills 0–11 only.
- **Armor's Dexterity and Stealth bytes are signed.** Plate costs 3 Dexterity and up to 20 Stealth; some leathers add Stealth.
- **Items' models** (Borg5) aren't in the tables; the code finds them by an item's position in its table (`ItemTables.ItemModels`, `0x8006D018` in 1.0), and the importer puts each on its record as `Model`. Weapons: 66 positions in a byte list ending with `0xFF` (`CodeTable.WeaponsWithModels`), each with its u16 Borg5 at the same index in `WeaponModels`; the weapons without one are the natural weapons, such as bites, and some others. Shields: 17, the armor table's positions 51 (Sheridans Shield) to 67 (Chaos Shield), in a switch in code (`ArmorDB::GetBorg5`), not data, so the importer carries them as a literal table (`ItemTables.ShieldModels`), checked against the switch in all three ROMs. Every other position, the other shields and all body armor, gets `ShieldNONE` (`0x38F9`), which means none. Items: six, in a u16 list of item table positions ending with `0xFFFF` (`ItemBorg5Search`) and the Borg5 at the same index: Letter to Txomin `0x0CCE`, Banner of Gwernia `0x09D0`, Horn of Kynon `0x34FB`, Kendall's Hat `0x3502`, Stormbreaker `0x3553` and Pandara's Amulet `0x3517`. Every model is a Borg5 the importer exports as a scene. The tables are identical in the three ROMs but sit at different offsets (`CodeTable.WeaponsWithModels`, `WeaponModels`, `ItemsWithModels`, `ItemModels`).
