# Plugins: the format, loading and merging (Phase 5)

The importer writes the base with `AidynRenewed.Plugins`' types, and the runtime and editor read every plugin through `PluginSet`. [ADR 0004](../adr/0004-record-ids.md) and [ADR 0005](../adr/0005-plugin-format.md) decide the format.

- **Load order** (`PluginSet.LoadOrder`): the base first, then `dependencies` first, `loadAfter` when that plugin is present, ties by ID. A cycle, or a folder not named for its plugin's ID, is an error.
- **Merging** (`MergePatch`) is RFC 7386 (a scalar replaces, an object merges, `null` removes), except that a **keyed list** merges element by element. The `[KeyedList]` attribute on a record property names the element's key fields; `RecordSchema` reads it, and the rest of the merge's knowledge of the types, from the serializer's metadata, so the merge and the record types can't drift. A patch element whose key the record has merges into it, one it lacks is added at the end, and `{ "index": 12, "$remove": true }` removes it. A list is keyed when something else names its elements by the key (a map's `objects` by `index`, a script's `nodes`, a map set's `chunks` by `row` and `column`, and so on: grep `KeyedList`); a list whose elements' identity is their position, or whose elements repeat, is replaced whole. `KeyedListTests` checks the base's keys are unique. The script VM refuses a removed node, as it needs node *i* at position *i*; inserting and removing nodes is left to Phase 5 (ADR 0005). A record object's `$schema` is ignored, for editors.
- **The conflict report** (`PluginSet.Conflicts`, `aidyn-renewed conflicts`, and a count in the editor's status line) lists every field that more than one plugin *patched*, by path (`damage`, `objects[12]`, `objects[12].position`, `chunks[9,8].music`). The definer doesn't count. `PluginSet.Setters(id, path)` gives everyone who set a path, the definer first, which the editor shows per field.
- **Validation** (`PluginSet.Validate`). Reads are lenient (`PluginJson.Options`: a view such as `DbRecord` reads part of a record, and a save skips what it doesn't know), so a typo in a patch would merge and be ignored. `Validate` reads every record once with `PluginJson.Strict`, which refuses an unknown field or `type` discriminator, a null the type doesn't allow, a missing field with no default, and a keyed list with two elements of one key. `ValidationReport` blames each problem on the plugin that last set its path. Every problem is an error, in any plugin: a mod for a newer engine gets an honest refusal rather than a half-applied mod. `LoadInstalledChecked`, which the runtime and the CLI load by, throws the report; the editor (`RecordBrowser`) shows it and loads the records anyway, since it's where they're fixed.
- **JSON Schema** (`RecordSchema.JsonSchema`, `aidyn-renewed schema <dir>`): a draft 2020-12 schema per record type, exported from the strict options, so a schema refuses what validation refuses: `<type>.schema.json` for a record and `<type>.patch.schema.json` for a patch (every field optional and nullable all the way down, and `$remove` on keyed lists' elements). `SchemaRoundTripTests` checks a real record of every type against its schema.
- **The record-type registry** (`RecordTypes.Registry`, ADR 0004) ties each type's name to its class, its key kind (`KeyKind`: `Db`, `Borg`, `Decimal`, `Nested`) and whether there's one of it; every other list of types is built from it. `RecordId.TryParse`, `Hex` and `Decimal` enforce the key's shape, so one record has one ID string. A type's records read as its class or a declared view (`DbRecord` for the seven DB types), and `Get`, `TryGet` and `All` refuse any other class. Scenes, textures, UI images, samples and animations have no class: they're assets alone.
- **Reading records.** `PluginSet.Get`, `TryGet` and `All` read the merged JSON as a record type once and keep it, so every later call returns the same immutable object; nothing changes the merged JSON once the set has loaded, so the cache never goes stale and is safe from the audio thread. A singleton type (`aidyn:camping/0`, the sky, the sounds, the credits and the like) is read with `Singleton` or `TrySingleton`; a mod patches it rather than adding another.
