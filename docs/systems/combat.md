# Combat: battle mode (2.5, 2.6, M3)

The original's combat, read from 1.0's code and checked in the combat checkpoints, and its port. Everything up to [The port](#the-port) is the original: its code, what it keeps in RAM, its states, a turn, an attack, the AI, spells in a turn, what spells look like, what the bodies hold and the special battles. [The port](#the-port) says which classes port what, what a battle tells its host, the traps, and where the port differs. What the player sees is in [engine-behaviour](../engine-behaviour.md#battle-mode).

Addresses are 1.0's. Names are in the symbol map, prefixed `Combat.`, `Combatant.`, `TurnOrder.`, `ArenaGrid.`, `TargetSet.`, `EnemyAI.`, `AiScores.`, `CombatGui.`, `CombatMenu.`, `CombatMarkers.`, `CombatSpellFx.`, `CombatCamera.`, `CombatRadar.` and so on, all coined but `ProcessCombatCamera`. Fields marked **checked** were read in the combat checkpoints ([rig](../reference-rig.md#checkpoint-library)), one battle against ten rats; the rest are read from the code.

Combat is game mode 2 (`Game.Mode`, `0x800D80C8`). `ScreenFade.Step` (`0x8001F330`) calls `Combat.Frame` (`0x80022BA4`) each frame, and the mode it returns is the next: 2 to stay, 1 trek, 3 the pause menu, 6 the post-battle windows, `0xC` a cut-scene, `0xE` a cinematic, 0 leaves the game.

## In and out

**The setup block** (`0x800D9456`–`0x800D9485`, **checked**: empty in checkpoint 01, filled in 02) is what every source fills, and `BattleSetup` is the port's:

| Address | Holds |
| --- | --- |
| `0x800D9456` | 1 when filled; 0 makes the debug build's random test battle |
| `0x800D9458` | 12 entity IDs, 0 ending them (ten rats, `0x026E`): the first four start on the field, the rest are reserves |
| `0x800D9470` | bonus loot: an item, or a chest if its type is 8 |
| `0x800D9472` | the encounter flag (1321 for the rats; the Goblin Ambush's is 978) |
| `0x800D9474` | 1 if winning remembers the monster party's map object; then its index (`0x800D9476`), map set (`0x800D9478`), row and column (`0x800D947A`, `0x800D947C`) |
| `0x800D947E` | the collision byte, 0–2: how the party's placed. 2 is an ambush |
| `0x800D947F` | the arena, 0–27 |
| `0x800D9480` | the animation byte, 0–3: the enemies' spawn set is 4 less |
| `0x800D9481` | can flee |
| `0x800D9482`, `0x800D9484` | the monster party object's flag slot A (`+0x1C`) and its flags (`+0x14`), which `Combat.StateVictory` evaluates (`MapObjects.GateHolds`, `0x800116AC`) before it remembers the party |

- **Filled by** `BattleSetup.FromMonsterParty` (`0x800094B4`, the port's `BattleSetup.WithParty`: `Wanderer.Tick`, `IMapObjectHost.Talk` and `BattleSetup.Against`, below), `CampEncounters.Load` (`0x800096DC`: collision byte 2, animation 0, no fleeing, no loot or flag) and the script ops. `Wanderer.Tick` writes collision byte 2 and the animation byte by what the player was doing as it noticed him (3 running, 2 walking, 1 sneaking, else 0); `Talk` writes animation 0 and collision 0 with the player in a cone ahead of the party's body, else 1 (`0x80010AE8`–`0x80010B74`).
- **The enemy list** (`BattleSetup.FillEnemies`, `0x80009374`) is three passes over a party's eight kinds: each kind's least, in order, stopping at the party's most or 12 (`BattleSetup.SureKinds`, `0x80008EC8`); then, unless that reached the most, a `Range(0, most − least)` more of each kind whose most is above its least, in order, stopping the same way, and none at all if it comes to under the party's least (`BattleSetup.ChooseKinds`, `0x800090A4`); then, where the party's average level is below the enemies', each kind loses 0.3, 0.2 or 0.1 of its count by the party's level × 3 over the enemies' (`BattleSetup.TrimByLevel`, `0x800088E4`, the shares at `0x800CD470`), removed from the front, an entry shifted into a removed one's place being passed over. A list come to nothing is one Skeleton (`EntityList[0xBB]`, `0x0263`). So the field is the sure ones first, not a shuffle. `Combat.ForbidFleeForBosses` (`0x8005CCCC`) clears the flee byte for the 12 entities at `0x800D2688` (up to `0xFF`) and sets it for the Shadow, whose place it compares with as an immediate (`addiu v0, zero, 0xAC` at `0x8005CCE8`), and `Combat.ApplyFleeRuleByFlag` (`0x8005D054`) has the last word by flag ([hardcoded-content](../hardcoded-content.md)).
- **The arena** (`BattleSetup.ChooseArena`, `0x80008698`, for every battle but a cut-scene's, below) is by the terrain of the chunk the player's in (`World.GetTerrain`), through a jump table at `0x800CD400`. A range is a roll between them, inclusive (`Rng.Range`):

  | Terrain | Arena | Terrain | Arena |
  | --- | --- | --- | --- |
  | 0, 7 | 6–7 | 11 | 23 |
  | 1, 24 | 2–3 | 12 | 22 |
  | 2 | 0–1 | 13, 25 | 27 |
  | 3, 27 | 14–15 | 14 | 24 |
  | 4 | 19 | 15 | 25 |
  | 5, 17 | 4–5 | 16 | 26 |
  | 6 | 18 | 18 | 20 |
  | 8 | 12–13 | 19, 23, 26 | 8–11 |
  | 9 | 17 | 20 | one in two 6–7, else 8–11 |
  | 10 | 16 | 21 | one in two 2–3, else 8–11 |
  | | | 22 | one in two 0–1, else 8–11 |

  A terrain of 28 or more writes nothing, so the last battle's arena stays. Nothing but the debug build's random battle reaches arena 21. Terrains 20–22 draw `RollD(1, 2)` first, 1 for the first range. The importer carries the table as a fact on each terrain record (`TerrainRecord.Arenas`, `AidynRenewed.Rom.Engine.Arenas`).
- **A script's battle** (`BattleSetup.Scripted`, `0x80050804`, as its battle op ends it) fills the block from the script: its `AddEnemy`s, the collision byte (`+0x112` of the script's state), the arena (`+0x114`, above 27 made 0 at `0x80050888`; 0 when the script sets none) and the animation byte (`+0x113`), the block marked filled, and fleeing unless the script is a cut-scene (mode byte `+0xAA` ≠ 1). That's every cut-scene's battle, each of which sets its arena. **A conversation with a monster party** fills it again as the conversation ends: `Conversation.End` calls `Transition.AfterScript` (`0x80051AD4`), which by the ending kind (`+0x90`) sets `TrekLoop.State` to 5 or 7 for a shop or training, or for a battle (2) calls `BattleSetup.Against` (`0x80051A4C`). With a party talking (the script's `+0x78`, its body's map object), that sets `TrekLoop.State` 2, the collision and animation bytes 0, and calls `BattleSetup.FromMonsterParty` on the party's object with its flag C (`+0x20`): its enemies rolled, fleeing allowed, the party remembered on a win, and **the arena by the terrain** (`ChooseArena`), over what the script wrote. No such conversation sets an arena. So Kitarak's battle, in his room in the goblin camp (map set 1, C01, terrain 16), is in arena 26 (M19, the dark wooden floor), not arena 0's forest. The port's `Transition.AfterScript` applies `BattleSetup.Against` for a conversation's talker (`GameSessionTests.KitaraksBattleIsInHisTerrainsArenaNotTheScriptsUnsetOne`). With no party talking, `Against` does nothing and no battle starts, where the port starts the script's; no conversation in the game but a party's ends in a battle, so only a mod reaches it.
- **The switch.** `TrekLoop.QueueState(2)` (`0x8001FF04`) fades out; trek's state 2 marks trek to be built again on return (`0x800DB067`) and returns mode 2.
- **`Combat.Init`** (`0x80022D1C`, on the first frame, while `0x800DB0A4` is 1): takes down trek's HUD, allocates the combat struct (`Combat.Reset`) and loads the combat strings, sets map set 16 (`0x800D8414`) and the arena's chunk (`0x800D8416`), and starts the zone engine in mode 1 (`InitZoneEngine(1, 0)`, `Zones.Mode`): trek's chunk streamer, collision, lights, sky and weather, over the Battle arenas, with the zone engine's point at (20, 20) in the arena chunk, the shadows' distance 128, and the battle's song chosen in `Zones.SetMapSet` (one `Below(5)` of the map set's five, or `Below(4)` of four without the Expansion Pak). `Combat.Setup` (`0x8005D15C`) fills the struct: the counts, the arena grid, a combatant and a body for each living party member and enemy on the field, Sholeh moved to the party's side if she's in the first four, the leader, whether there are flee points, the turn order and the flee rules by flag. Then the GUI, a body for each combatant (`Combat.CreateBody`, `0x8005C474`), the first turn's line, the camera on the current combatant's body (`Camera.SetEye`, `GiveCameraToPlayer`, `CombatCamera.Reset`), the first turn (`Combat.StartFirstTurn`, `0x80022C9C`: its line, the radius, the ring and the field, but not the clock), the effects, and state 31 with the fade in, a sixtieth a tick (`0x800CE308`). The Goblin Ambush's flag (978) makes it non-lethal, sets the hold's count to 2 and heals the first member ([The special battles](#the-special-battles)). Its `0x800E6850` and `0x800E6860` are `Combat.StateMoving`'s walk positions, not cameras.
- **`Combat.Exit`** (`0x80023060`, after every frame, acting the frame a state asks, `0x800DB0A8`): marks the setup block used and clears `RememberParty` (`0x800D9474`); after the Goblin Ambush (978), however it ends, adds the party's first member's **base** Strength to its current and modified (`Stats.AddCurrent`: the ambush's second hit took it to 0, so a battle ended before that doubles it), sets flag 47, rewrites trek's kept place (`Zones.SavedPosition`) to Oriana's hut (map set 6, E03, (5.9, 0.5, 3.0), the eye at the position, facing (1, 0) in the kept field `0x800D9078`, which `InitGameTrek` copies back to the body's own reversed one, `+0x20`, so he faces (−1, 0), toward Oriana), as the map set's named place 0 (`Zones.SavedPlace`, `0x800d9092`), so trek's first frame walks into her first cut-scene and its end chains into the next ([scripts](scripts.md#the-world-it-plays-in)) and heals Alaron in full; takes every effect off every combatant (`Entity.ClearEffects`, `0x80071830`: the potions' but Stealth's, kind 0x10, and the 15 timed spells'; hit points stay); frees the GUI, the effects, the bodies, the struct and the zone engine; and last takes the dead out of the party (`Party.AfterBattle`, `0x80074EE8`, [Deaths](#deaths)). The bonus loot (`0x800D9470`) is never cleared, so a script's battle, which doesn't write it, pays out the last monster party's again. Where it goes is the mode the state returned:
  - **A win** (state 12, `Combat.StateVictory`, `0x80022450`), once faded out: `Combat.Exit` asked; for a monster party's battle alone (`RememberParty`, which only `BattleSetup.FromMonsterParty` sets), the encounter flag set, and if it still reads 0 (flag 0, a party with none, or a derived flag) while the party's own gate, its flag A (`MapObject.Enabled`), holds (`MapObjects.GateHolds`, `0x800116AC`, over `0x800D9482` and `0x800D9484`, which `BattleSetup.FromMonsterParty` copies from the object's `+0x1C` and `+0x14`), the party remembered (`MapObjectMemory.Remember`, kind 5, three map loads: [saves](saves.md#map-objects-memory)); `Combat.SetKillFlags` again; the snapshot, black; `PauseMenu.PrepareLoot` (`0x80048FF8`), which hands the loot window the loot and the gold and **adds the gold to the party at once**; the experience pool to `PauseMenu.ExperiencePool` (`0x800D94D0`); and mode 6, the post-battle windows: pause states 5 (experience and training) and 6 (loot) ([ui](ui.md#after-a-battle)). The loot window closes to trek (`PauseMenu.CloseToTrek`, `0x80048F40`), mode 1, built again at the kept place exactly and fading in at 1/30, as after fleeing. State 16 never runs for a win: the `Combat.NextState` 16 that `StateVictory` writes is never read.
  - **A loss** (state 13, `Combat.StateDefeat`, `0x80022590`), once faded out: `Combat.StartGameOverScript` (`0x8001F860`) heals the party's first member in full, finds the first dialogue object in the Dreamscape's map (Borg9 `0xD5F`) whose script is `CodeTable.GameOverScenes`' first, `0x0512` (the other two are never read), starts it as using it would, and sets state 21 (`Combat.StateLeaveToScript`, `0x800227D4`), which returns mode `0xC`, the cut-scene. The script's ending kind 2 (`CodeTable.ScriptEndings`, `0x800DFE1C`, kept in `CutScene.EndingKind` `0x800DFE4C`) makes the cut-scene return mode 0, the title (`Title.Frame`, `0x8001B154`): nothing is saved or reloaded. A non-lethal battle (`Combat.NonLethal`, `0x800DA0DC`, which `Combat.Init` sets for encounter flag 978 alone) instead sets the encounter flag, remembers the monster party fought with no gate check, sets the clock to 6:00:00 the next day whatever the hour (`World.SetDate`, `0x8007B914`, the day byte increased), and returns mode 1. The port's game over goes back to the title, its intro cards first, as the original's restart does ([ui](ui.md#coming-back-to-it)).
  - **Fleeing**: the pause menu's Flee, offered only in state 14 and while `0x800D9481` is set, with no confirmation, roll or line in the log (the combat strings' "The Party flees" is never read): it sets `Combat.NextState` to 20 (`pauseMenuSelectCallBack`, `0x800403AC`), and once the menu has rolled up, `Combat.StateLeaveFled` sets `Zones.Fled` (`0x800D9376`) and returns mode 1. `Zones.Fled` is read only by `InitZoneEngine` and cleared by `Zones.ResetBreadcrumbs`: fleeing costs nothing else, but the party isn't remembered and `Combat.Exit` takes the dead out as after any battle.
- **Back in trek.** As trek faded out, `TrekLoop.Free` kept where the player stood, his heading, the camera's eye and the chunk (`Zones.SavedPosition`, `0x800D906C`, 0x2C bytes). Trek is built again there (`InitGameTrek`, `0x80020F40`), the body put at the kept place exactly, not set down, its heading the kept one (both the body's `+0x20` and `+0x28`), and the camera's eye at the kept eye, aimed at the body (`Camera.SetEye`, `Camera.SetTarget`). Having fled, it's the **breadcrumb** farthest from there instead, which `InitZoneEngine` (`0x8000DF84`) copies over the kept place while `Zones.Fled` is set, so the heading and the camera's eye are the breadcrumb's too: each is the same 0x2C record (`SaveZoneEngine`, `0x8000E3D4`: the position, the heading at +0xC, the eye at +0x14, the chunk and the map set), and the checkpoints show the kept eye 5 to 6.5 behind the body along the heading. He faces as he did when the breadcrumb was kept, seen from behind as he was then, not from where the battle began. The port keeps the eye with each breadcrumb and puts the camera there (`Breadcrumb.Eye`, `TrekLoop.Resume`); every other return to trek, a win's among them, finds the camera where trek left it, which is the kept eye. The Goblin Ambush's end is the exception: `Combat.Exit` puts the eye at Oriana's hut with the body, and `TrekLoop.Keep` doesn't move the camera, which is left so because her cut-scene starts on trek's first frame. The breadcrumbs: trek's zone engine keeps where the player stands every 120 ticks, unless the nearest kept in the map set is under 10 away (the places within their chunks compared, as though in one), in a ring of 15 (`Zones.Breadcrumbs`, `0x800D90E0`; `HandleZoneEngineFrame`, `0x8000E784`), and `Zones.FindBreadcrumb` (`0x80009A48`) takes the farthest in the same map set, a chunk counting 100 a row or column, the last of equals. Every time trek is built, all 15 are where the player stands (`Zones.ResetBreadcrumbs`, `0x8000DF00`), so they aren't saved. Checked in checkpoints 01 and 02. The monster party that started the battle is remembered only on a win; after fleeing it's back at its home node with every wanderer, and can hunt again.
  - **The Shadow merging**: state 17, whose first frame is `Combat.MergeShadow` (`0x800675C0`) and mode `0xE`, the Shadow's cinematic (record 1, `Cinematic.Load(1, 4, 1)`, [cinematics](cinematics.md)), played once combat is freed; then trek where the battle began. **Vanishing**: states 29 and 30, then trek where the battle began. Neither gives rewards or sets an encounter or kill flag ([The special battles](#the-special-battles)).

## The arenas

The Battle arenas are `aidyn:mapset/16` ("Battlefields", 150 to a cell): 28 chunks, the arena number being the chunk's place in the map set's list (`Zones.ArenaChunks`, `0x800DCA74`, which the importer reads), but only 15 maps. Chunks sharing a map are the same arena, terrain, scenes and music alike. `Zones.SetMapSet` puts the zone engine's point at (20, 20) in it.

- **What they place:** reference points and up to 12 scenes, all always there (flag 0 inverted), some only with the Expansion Pak. No lights, sounds or other objects. The 46 × 46 arenas are a flat disc of 24 triangles; the scenery reaches far past the collision, to ±300 in I11.
- **Arenas 24 and 27's floor streaks past its rim** (M15 and M21, scene `0x3671`, one model, Borg2 13936, under terrains 14 and 13, whose skies aren't drawn). It's one wrapping material (flags `0x305C`, both wrap bits) with a 32 × 32 texture (Borg1 4894): an octagon of radius 23 lit by its vertex colours (white at the middle, 51 at the rim), and a skirt from the rim down to four corners about 250 out, black at the corners. The disc's texture coordinates are a plane in X and Z, about 7 units a tile in S and 4 in T, each triangle shifted by whole tiles. The skirt's corners would need 35 to 60 tiles, past the ±16 a vertex's 16 bits hold at the lists' 0.5 texture scale, and the data holds them wrapped by whole 32-tile turns, so its triangles squeeze and shear the texture into long streaks fading into the dark (`GeometryTests.ArenaFloorsSkirtHoldsItsTextureCoordinatesWrappedPastSixteenBits`). It's the ROM's own vertices, and 1.0 wraps the tile as the port does (`Scene.SetTextureTiles`, [rendering](rendering.md#wrapping)), so the original streaks the same, as a cartridge longplay bears out (Oct 23, 2026).
- **The points, by name** (`FindReferencePointName`, `0x8000B7C8`, with the combat strings' `%s%u%c`, `good`, `bad` and `flee%d`): every arena has the 40 spawns `good0a`–`good4d` and `bad0a`–`bad4d`, and `flee0` up to `flee7`. Arenas 17 and 20 have no flee points, so enemies there can't flee (`0x8005E76C` sets `+0x5440`).
- **Which spawn** (`Combat.FindSpawnPoint`, `0x8005C210`; `Combat.SpawnPosition`, `0x8005C294`): `%s%u%c`, the side's word, a set number and a letter. The party takes `good` and the enemies `bad`, swapped in an ambush (collision byte 2). Both sides start in set 4 − the animation byte, and reserves in set 0; in an ambush the party's set moves by the Ranger's roll (`Party.BattleAmbushRoll`, `0x80076C60`): the member, dead or not, with the strictly best modified Ranger who has the Stamina for it (5 less the Ranger, at least 1) rolls a d100 against Intelligence × 3 + Ranger × 10; failing, the set is 4 (3 with animation 3); under it, the margin's step (`Party.SkillCheckStep`) and the Stamina spent: step 1 moves it a set up (not with animation 0), 2 and 3 leave it, 4 or more a set down (not with animation 3); with no one to roll, no draw and no move. The party's letters are the living members' count so far, Sholeh's always `d`, and an enemy's its place in the list. A missing point stops the original (`FindReferencePointName` asserts). The spawn's x and z, truncated, are the combatant's cell (**checked**: Alaron's `bad2a` at (52.9, 52.3) is cell (52, 52)), and the body is made a unit up there and set down (mode 0).
- **Which way they face**: one draw each, as they're made: `Range(1, 3)` for the party, and for the enemies `Range(5, 7)` with collision byte 0, else `Range(1, 3)` too; the direction's vector is `Combat.DirectionVectors` (`0x800D27A8`, north (0, −1) round to north-west), and the body's heading is that way (the original's body field is its negation).
- **The ring's teardrops** are drawn by code, not placed (`CombatMarkers`, `combatmarkers.cpp`): a pool of 20 copies of `aidyn:scene/0x0794` (`CombatMarkers.Init`, `0x800854A8`, at `0x800E3138`, 0x1C each), a blended billboard about 0.41 × 1.0 with a scrolling texture (Borg1 1937); the code sets no scale, turn or scroll, and draws each with the zone's colours and fog (`Zones.SetSceneColors`). `CombatMarkers.Update` (`0x80085548`) works the radius out first, then lays the ring round where the combatant **began its turn** (`+0x08`), not where its body is: its radius R is the field's plus the body's scaled radius (`+0x34`), plus that again for one with an AI record; 6 teardrops up to R 3, 16 up to 7, else 20 (`CombatMarkers.CountFor`, `0x8008580C`, the floats at `0x800D43C8` and `0x800D43CC`); the first due +Z and the rest round toward −X by `(360 / N) × 0.017453`, the way round kept in two statics never reset (`0x800E3130`, `0x800E3134`, from (0, 1)), so each ring starts a ten-thousandth further round than the last. Each is set on the ground as a body is (`CombatMarkers.RingPoint`, `0x80085240`): a sphere of 0.5 swept from 100 to −100 past see-through triangles rests 0.01 above the first facing it; a miss tries again from a little to the side of the ring's point (two draws, up to 0.25 each way, not adding up), four times, and one that misses every time takes the body's height and then half way between its neighbours'. The ring is laid out only as a turn begins (and as the field follows a combatant near the Shadow), and drawn every frame (`CombatMarkers.Draw`, `0x80085848`, from `Combat.DrawFrame`) but from `Combatant.ExecuteAction` to the turn's end (`Combat.ActionActive`, `0x800DB0CC`) and from `Combat.StateVictory`; there's no fade in. **Checked** in 02–04, 09 and 10, every teardrop.
- **The grid** (`ArenaGrid`, `0x800674A0`–`0x80068F7C`) is 100 × 100 cells of a byte a unit across in the arena chunk's own coordinates, index x × 100 + z, the height × 2 in the low bits and bit 7 for taken. `ArenaGrid.Init` (`0x80067960`) sizes it by the map's object grid (cell size × columns and rows, rounded half away from zero). `ArenaGrid.Fill` (`0x8005E900`) sweeps a sphere of 0.5 from 100 down to −100 through each cell's centre over the arena chunk's collision, see-through triangles included, the first facing it in the grid's order: the byte is twice the height it touches, truncated, and a miss is taken (0x80). Each combatant takes its footprint (`Occupy`, `0x8006820C`: from its cell on in +x and +z, none if any cell is outside), twice its scaled radius rounded half away from zero, at least 1 (the party 1, rats 2). **Checked** against checkpoint 02's. `WalkClear` (`0x80067E6C`) is a line over free cells with steps under 2; `HasSight` (`0x800684C4`) is the line in 3D for ranged attacks and spells, through the collision and the bodies between; `FindPath` (`0x80068CD4`) is a greedy walk of at most the grid's diagonal, which `StraightenPath` trims.

## A turn

1. **It ends** (`Combatant.EndTurn`, `0x80061300`): `CombatCamera.Reset` (`0x8008D210`, a glide stopped), the AI's target forgotten (`EnemyAI.ClearTarget`, `0x8005B998`), the cast chosen cancelled (the entity's `+0x3C` to `0xFF`; the selected spell stays), the acted flag cleared, a scroll or wand whose selected spell has no charges left taken off and gone (the entity's `+0x3D` of 5 with an item of type `0x11` or `0x0D`, `Entity.UnequipGear` `0x8006F5C4`) and no spell selected, state 1 and the ring shown again (`Combat.ActionActive` 0), the body asked to stand, the action put back (`Combatant.RevertAction`, `0x8006679C`) and with a flask in hand the weapon stowed (`Party.StowHeldItem`, `0x800763B0`), the last target forgotten if it's dead, then `TurnOrder.Advance`. Every end of a turn comes here: the skip, the action's result (state 4, 60 ticks on), the AI's rest, a weapon or flask taken in hand in the pause menu (19), Sense Aura's popup dismissed, and the AI's walk or turn with nothing to do (5, 6).
2. **The next** (`TurnOrder.Advance`, `0x8006AC4C`): nothing once the battle's won or lost (states 12, 13); the party's first member dead (`*GameState.Party`, not `Combat.AlaronSlot`) loses it (`Combat.Defeat`, `0x80023F98`: state 13 and the fade, or 28 in a non-lethal battle); the last combatant's body let go of its field (`TurnOrder.StopBody`, `0x8006A5C4`); then on through the round, its end building the next (step 7). Before each candidate the battle's end is checked (`TurnOrder.CheckEnd`, `0x8006A97C`, over `TurnOrder.CountActive`, `0x8006A880`, a reserve still to come counting as an enemy), and the candidate's radius, place and whether it can act are worked out (`Combatant.UpdateActive`, `0x8006615C`: not with no Intelligence, Willpower, Dexterity or Strength, nor immobilised), skipping it dead, unable or gone. Then the focus is on it, every combatant reads its body (`TurnOrder.ClearActions`, `0x8006AE64`, clearing the numbers to show), its turn begins, the clock moves on 600 (`World.AdvanceTurn`, `0x8007C01C`: `World.WrapYear` and `World.Update`, so the weather rolls if the part of the day changed; it ages no effects; **checked**, +600 a turn in 02–04), and a reserve that fled on arriving says "Enemy reinforcements flee" (`+0x543C`).
3. **It begins** (`TurnOrder.BeginTurn`, `0x8006A9C8`): the camera's given to its body (`GiveCameraToPlayer`, `0x80015E30`, which drops an R orbit) and anchored there; its line, "%s begins action", a newcomer's "joins the battle" (`0x7C`, clearing flag 10), or either overwritten by a performer's (`0xD0`); it reads its body (`Combatant.SyncFromBody`) and keeps where it starts (`SaveStartPosition`); the ring (which works the radius out again); its field (`Combatant.PlaceRingAndBody`, `0x8006627C`); then for a combatant with an AI record, its check to flee (`EnemyAI.CheckFlee`, `0x800572AC`: the leader's morale and its own against `RollD(2, 6)`) and state 8, otherwise a flask or spell carried over looked up and state 1, as `State` and `NextState` both, after the target sets are built. The Shadow's aura is the round's, not the turn's, and nothing sets a body down: bodies are set down once, as they're made.
4. **The field's radius** (`+0x21`, `Combatant.UpdateRadius`, `0x8005F29C`) is the first place in `Combat.RadiusByDexterity` (`0x800E0C20`: 0, 0, 0, 3, 7, 12, 16, 21, 26, 28, 30, 33, 36, 38) whose byte reaches the **modified** Dexterity, 14 past it (3 for 1–3, 4 for 4–7, … 13 for 37–38). Then each timed effect in its slot's order: Haste (kind `0x1E`) adds its level, and Stellar Gravity (`0x38`) takes its level away, leaving 1 if that's all or more; an effect's kind is its spell ID's low byte's place in the code's spell list (`0x800E2B40`). Then **1 at most while engaged**: an opponent alive and able within the larger of each body's radii, scaled (`+0x34`) or not (`+0x38`), plus 0.75 (`0x800D2810`), across the ground, both bodies read again first (`Combatant.IsWithinReach`, `0x8006011C`, from `IsFreeOfOpponents`, `0x8005F1B8`); this sets or clears flag 7 and stops a performance. Not engaged, 1 at most while performing, or 1 near the Shadow (`Combat.NearShadow`, `0x80023F34`: within 10, strictly, which logs the vortex line on the current one's). Then 13 at most, and 0 for Pochanargat (entity list place `0xAB`, `0x800E28EB`). It's worked out as each body is made, before each candidate in `Advance`, with each ring, and in the Shadow's battle as the combatant walks, so flag 7 is as old as that: **checked** in 09, where Brenna is engaged with a rat whose own flag is clear until its turn (10).
5. **The player** moves the body with trek's stick handler (`Body.ApplyInput`, `0x80014FEC`, fed each poll): R orbits the camera as in trek, and otherwise up on the stick is the way the camera looks, walking, running from 0.8 or sneaking with Z held, a party member turning 10° a poll. The field holds it: `Body.SetGoal` (`0x80015BD4`) keeps a centre (the combatant's place and the body's height as its turn began, `+0x274`) and a radius (`+0x280`) with body flag 4, and `Bodies.Process` (`Body.ClampToGoal`, `0x80014518`) puts the body's X and Z back on that **sphere** after it moves, before the bodies push each other, whenever it's at the radius or past it in 3D. So it slides round the edge, and on a slope reaches a little less far across the ground. **Checked**: 03's walked bodies are 10.0000 from their centres in 3D. Every body gets its field as it's made, about where it stands, and loses it as its turn ends. Nothing in the grid stops a body; the bodies' push does (`Crowd`). After each poll the combatant reads its body (`Combatant.UpdateFromBody`, `0x8005F784`): its footprint leaves the grid and takes it again where the body stands (`ArenaGrid.Vacate`, `0x800682E0`, and `Occupy`, the cell rounded half away from zero), its place is the body's X and Z exactly, the focus follows and its facing is the body's; a change counts a move (`+0x22`), the fourth sets flag 3 (**checked** in 02–04), and the target sets are built again. The radius isn't worked out again as it walks up to an enemy: `Combat.MovePlayerBody` (`0x80084CE0`) does that only near the Shadow, centring the field on the body.
6. **The action** ends the turn: an attack, melee or ranged by the weapon (`Combatant.ResolveAction`, `0x80065ACC`); a flask thrown or a potion drunk (action 3: `ThrowFlask` `0x80065600`, `DrinkPotion` `0x80064C84`); a spell (`CastCurrentSpell`, `0x80065C08`); Lay On Hands or Heal With Herbs (`ResolveHealer`, `0x8006591C`); the Troubadour (`StartTroubadour`, `0x800662F4`); a weapon changed in the pause menu; or a skip. `Combatant.ExecuteAction` (`0x80065F6C`) ends a performance, hides the ring, carries it out, applies the damage, checks for death (`CheckDeath`, `0x80065E98`) and starts state 2.
7. **The round ends** (`TurnOrder.EndRound`, `0x8006A62C`) when the list runs out: the Shadow's aura first (`Combat.ShadowAura`, `0x80023AD0`, which can end the battle); each performer pays a Stamina point or stops with none; every combatant's moves and flag 3 are cleared and its effects aged a round (`Character.AgeEffects`, `0x80071444`: the potions', the timed spells', and what they do); the reserves come in (`Combat.SpawnReserves`); the toggle flips and the next list is built. The leader's morale moves at each of the AI's turns, not here. Wins and losses are only ever found at a turn's change, not at a death.

**Turn order** (`TurnOrder.Build`, `0x8006A16C`). A combatant's turns a round are by its **base** Dexterity (`Combatant.TurnsPerRound`, `0x8005F4D0`): 1–17 one, 18–24 one and two by turns (the toggle), 25–29 two, 30–34 two and three by turns, 35 and up three. The list is grouped: every third turn first, then every second, then every first, each group in random order (`Rng.Range`, drawing again on a repeat). Checked in 02: four party members and four rats gave `[1,3,0,2, 3,2,1,5,4,7,0,6]`.

**Win and loss** (`TurnOrder.CheckEnd`, `0x8006A97C`): no party member active is a loss (`TurnOrder.Defeat`, `0x8006A780`: state 13 and `Combat.Defeat`, then with a current combatant the party's line, `0xD4`, and in a non-lethal battle Alaron's own over it for good, `0x74`, his portrait locked), and no enemy active with no reserve left a win (`TurnOrder.Victory`, `0x8006A804`: `Combat.SetKillFlags` `0x80067860`, `Combat.TallyRewards` `0x8005E2AC`, state 12, the fade out at the battle's 1/60, and with a current combatant the victory line but under encounter flag 978). Alaron's death is a loss alone (`TurnOrder.Advance`, straight to `Combat.Defeat`, with no line). `Combat.Defeat` (`0x80023F98`) is state 13 and the fade out (`Combat.EnterDefeat`, `0x80023FD0`), or in a non-lethal battle state 28 (`Combat.EnterDefeatWait`, `0x80024014`).

**The kill flags** (`Combat.SetKillFlags`) read the enemy list's first four entries, stopping at the first empty, and set the flag of each boss among them (a jump table at `0x800D2B60`, by entity list place from `0xA8`): Kitarak 154, Pochanargat 3204, Shamsuk 458, Ksathra 3738, Shatrevar 3737, Mehrdad 3736, Golnar 3735, Nasim 3734, Behrooz 3733, Assim 3739 and Lugash 533; the Lizard Man Boss, the Marquis, the Shadow, Sheridan and four more set none. Whether the boss fell or fled doesn't matter, and script battles count. It runs twice a win (`TurnOrder.Victory` and `StateVictory`) and never on a loss or a flight. Its writes don't bring the flag network up to date, and the only read after the first is `StateVictory`'s of the party's gate, so a boss's journal entry is told when something next reads a derived flag: as trek comes back where loading the chunks does, else later. Kitarak's waits in his room until its chest, the journal or leaving; the port's is told as trek fades in, the user's choice ([flags](flags.md#when-the-network-comes-up-to-date)).

**Rewards** (`Combat.TallyRewards`), as the battle is won, before the fade: the loot inventory (`+0x4FB4`, 64 stacks) and the pools are made; for **every** entry of the enemy list, killed, fled or never come alike, its experience (the entity's `+0x7C`, the DB's reward byte × 50: a rat 100) and its chest (the entity's `+0x7E`, the chest DB's ID `0x7FF` + the byte, through `Combat.AddChestLoot` `0x8005E0F0`); then the bonus loot (`Combat.AddBonusLoot`, `0x8005E238`: a chest if its type is 8, rolled with no entity, else one of the item, worth no experience); then each living member gains the whole experience pool (`Character.AddExp`, `0x80071528`, times 1.5: dead members gain nothing, and an ally in the enemy list gives nothing); and last the gold pool is **doubled** (`sll` at `0x8005E400`). A chest rolls, in this order, on the one stream: its gold (`Range` between its bounds, drawing nothing when they're equal); the enemy's own armor and shield, each by the chest's chance (`RollD(1, 100)`) if it has them, and its three weapons, each only of a class that drops (`Combat.DropWeaponClasses`, `0x800D26C8`: Hafted, Missile, Pole, Sword and Thrown) (`Combat.RollEquipmentDrops`, `0x8005DC78`); a reagent by its chance, then which (`Range(30, 32)`: spice, herb or gemstone) and how many; then the six drops (`Combat.RollChestItem`, `0x8005DF38`), the first two between their counts. **What's looted adds to the experience pool**: a weapon its `ExpModifier`, armor its `ExpBonus`, another item its `ExpMultiplier` (the reagents 5, the Sapphire Gem 500), a potion nothing; a reagent once whatever the count, a drop times its count. **Checked**: the original's `TallyRewards`, run on checkpoint 11's RAM, gives 12's pool of 1000 and +1500 to each member. The checkpoints can't show the doubling or the items' worth, as the rats' chest has no gold and its Beast Hides are worth 0.

**Morale and fleeing** are [The AI](#the-ai)'s: the check to flee comes at an AI's turn's start, before its state is set.

**Reserves** (`Combat.SpawnReserves`, `0x8005D914`, at a round's end, checked in 09) are [An attack](#an-attack)'s.

### Deaths

- **The died flags** (`Party.SyncMemberFlags`, `0x80074A4C`, the docs' `Party::CheckDeaths`) are set for each dead member and cleared for each living one (`CodeTable.PartyDeathFlags`, `0x800D3718`), at every party member's death (`Combatant.Death`) and in `Party.AfterBattle`. Alaron has none.
- **Sholeh's 622** is set at the start of `Combatant.Death` (`0x80062080`) for any combatant whose entity is hers (`0x024D`), ally, enemy or member.
- **The dead leave** after every battle (`Party.AfterBattle`, from `Combat.Exit`): the flags written, then each dead member in order has every kept sheet of theirs erased (`Party.EraseKeptSheetsOf`, `0x80017F84`) and is stripped into the inventory, worn gear, weapon, armor and shield (`Party.RemoveMember`, `0x80075080`, through `Party.StripMember`, `0x80074FE4`), and the rest move up (`Party.Compact`, `0x80074F78`). Their joined flag stays set and their left flag clear. **Checked** by running it on checkpoint 12 with Rheda and Sholeh at 0 hit points. Alaron reaches it healed: the game over heals him first.

## An attack

Read from 1.0's code and checked by running the original's own functions on the checkpoints' RAM.

**Target set A** (`+0x4E64`; `TargetSet.Rebuild`, `0x80069264`) is built at a turn's start, as the combatant moves (`UpdateFromBody`), as an aim is put away and by other callers; while a player aims (states 9, 10, 18) it isn't rebuilt on idle polls. `Rebuild` empties it, finds the candidates (`FindAttackTargets`, `0x80069304`: everyone in play `Combatant.CanAttack`, `0x80060590`, allows; one may be chosen), selects the first, and keeps the cursor on the last target (`+0x10`), else where it was (`RestoreCursor`, `0x8006A05C`). Without an action, and not healing, it stays empty.

- **`CanAttack`**: never the Shadow (entity `0x0226`: the target's entity against the entity list's byte at `0x800E28EC`, its place `0xAC`, plus `0x200`, at `0x800605A8`–`0x800605D4`); not healing, a target on the other side, not dead or gone, while the attacker has an action; its weapon reaching (`CanReachWithWeapon`): a flask always; melee and healing within reach (`IsWithinReach`, the bodies' radii plus 0.75); ranged from distance 3 to the weapon's range, truncated, with no opponent within reach; melee-or-ranged anywhere in range. Then **`ArenaGrid.WalkClear`** (`0x80067E6C`) over the grid between the two cells, or failing that **`ArenaGrid.HasSight`** (`0x800684C4`) from the attacker's body lifted by both heads' heights to the target's body's centre: the two lifts (the entity's height less the body's radius) are worked out for each, but the second block, pasted from the first with only its registers changed, adds the target's to the attacker's point too (`0x8006079C` and `0x800607DC`, both to `sp+0x24`; the target's vector at `sp+0x60` is never lifted), so the line comes steeply down to the target's middle and a body just before the target blocks it. `CanCast` lifts the target's own point. The port runs it head to head ([Where the port differs](#where-the-port-differs)). The line is a sphere of 0.1 swept through the collision, see-through triangles included, and no other living body within its unscaled radius of the line, which runs on past both ends.
- **`WalkClear`** steps the line's longer axis cell by cell: each must be inside, not taken unless the end is a step from it, and a step from the last unless the end isn't. A step is a rise under 2 in the grid's half units (`IsStep`, `HeightDifference`). But it steps only toward +X or +Z: going the other way its loop never starts and the line is clear unchecked, so a target with a smaller X (or Z, for a line longer in Z) never needs the 3D test.
- **The action** (`+0x25`, `Combatant.SetDefaultAction`, `0x800672D4`): no weapon, none, so **unarmed party members can't attack**; range 0, melee; else ranged, or melee-or-ranged for a Breath, a Spit or Spikes (`Weapon.AllowsMelee`, `0x8007B730`). Enemies have weapons too: a rat's is Rat Bite (`aidyn:weapon/0x0702`).

**Aiming** (state 1's A, `Combat.InputTurn`, with the stick centred and R let go): set A is built again, and with candidates `TargetSet.BeginAttack` (`0x800694A8`) orders them (`OrderByAngle`, `0x8006975C`) and puts the cursor on the last target, else where it was, else the first; state 9, the camera given to the cursor's body. A bow, a thrown weapon that flies or a flask (`+0x8A`, `Combatant.UpdateDrawnFlag`, `0x80066A2C`, through the bow list `0x800E0C08` and the thrown list `0x800E0C14`) takes state 18 instead, a free cursor at the target. The order is by where each body stands from the attacker's against its body's own heading field, the opposite of where it looks: ahead and to one side by the sine's size, descending; then behind and the other side, ascending; then ahead and the other side, ascending; then behind and the one side, descending (`Vec2.Cosine`, `Vec2.SignedSine`, a selection sort whose ties go to the later). It sets only the cycling order and the cursor's place.

**State 9** (`Combat.InputAttackTarget`, `0x800842C4`), each poll, edge-triggered, with no repeat:

- **Start** pauses, and the pause comes back to state 1, the camera to the combatant.
- **B, Z or L** put it away (`Combat.ReturnToTurn`, `0x80083C70`): state 1, the healing modes off, the focus on the combatant, both sets built again, the camera back. The body stays turned.
- **A** confirms (`ConfirmAttackTarget`, below).
- **The stick or the D-pad**, left, steps the cursor +1 through the order, and right −1 (`0x80084420`), the camera to the new target and the attacker's body turning toward it 10° a frame (`Combat.AimAtCursor`, `0x80084334`).
- **The camera**: with the cursor's body over 5 from the attacker's, the eye's goal is 4 behind the attacker, away from it, and 1.5 up (`CombatCamera.PullBack`, `0x8008D22C`), with `Camera::Mode1`'s last flag clear, which skips its rise, its leash and its rescue.

**State 18** (`Combat.InputThrownTarget`, `0x80084BA0`): C-left and C-right step the candidates; the stick moves a free cursor 0.8 a frame, on the frame's first pad event only (`Combat.Controls`, `0x80083B00`, hands each event its place in the frame), whatever the stick's size past the dead zone (a tenth a way) and whatever the frame's ticks, turned by the camera (`Combat.StickToArena`, `0x80084570`) and kept on the grid and within the weapon's range, and set A selects the candidate whose body is nearest it, within a unit (`0x80084A24`); A confirms the same way.

**The turn to face** (`ConfirmAttackTarget`, `0x80084078`): the target's slot goes in `+0x14`, set B is emptied and A keeps its selection but loses its candidates, the camera goes back to the attacker, its facing points at the target and its body's turn starts (`Combatant.FaceCombatant`, `0x8005FD28`), state 6. State 6's input (`Combat.InputFacing`, `0x80085018`) snaps the heading to the goal on every poll while the body's turning flag (`0x20`) is set, so the 10° turn never plays: **state 6 takes two frames whatever the angle**, then `Combat.StateFacing` (`0x800221B0`) carries out the attack.

**`Combatant.ExecuteAction`** (`0x80065F6C`), in order: a performance ends; the target is the last (`+0x10`); set B is emptied; the attack is resolved (`ResolveAction`, `0x80065ACC`: melee, ranged, or for melee-or-ranged melee if `CanAttack` holds as melee; then the attacker's request by its weapon's animation byte, `Combat.AnimationByWeaponClass` `0x800D27E0`: 0 → 16, 1 → 17, 2 → 13, 3 → 12, 4 → 15, 5 → 14, else 18); the Goblin Ambush's hold on Alaron (`Combat.ShadowFightTrick`, `0x80065DCC`); **`CheckDeath`** (`0x80065E98`) at once, before any hit point goes: a blow that takes them queues "%s killed" (`0x50`) and calls **`Combatant.Death`** now, or with a Cheat Death on the target queues "%s cheats death" (`0xFC`); the attacker's moves set to 1; **the damage stored on the target** (`+0x29`, a byte); the camera's glide from the attacker to the target (`CombatCamera.StartGlide`); and state 2 with `ActionActive`. The acted flag stays down (only `PrepareCast` sets it), so a weapon's spell rolls its own margin.

**Melee** (`Combatant.MeleeChance`, `0x800622C4`, every step truncated to 16 bits):

- The attacker's modified Strength and Endurance, base Level, the weapon's hit, 6 × its weapon skill (the modified one, `Skills.WeaponModified`) and 2 × Warrior.
- Less the target's 2 × modified Dexterity, base Level and shield defence (`Combatant.ShieldDefence`, `0x8005F6B0`: the shield's defence × the shield skill + Warrior, a byte, so Warrior counts without a shield). The Dexterity and shield don't count against a target held fast (`IsImmobilised`).
- 20 more from behind, and Thief × 10 (`SkillTerm`, `0x80062ED8`).
- × 1.15 (`0x800D2964`) against a target with no Stamina; the height, c + h × 0.05 × c, with h the attacker's cell's height byte less the target's (`0x7F` off the grid); × 0.8 with no Stamina of its own; × 0.9 at night; the aspect (`AspectScale`: a Lunar attacker × 1.25 at night and × 0.75 by day, a Solar one the other way round, `0x800D2990`); the Troubadour (`TroubadourScale`); at least 5.
- **From behind** (`Combatant.IsBehind`, `0x8005FB54`): the point the distance away along the attacker's facing lies within half a unit of the target in X and Z (`IsAimedAt`, `0x8005FA44`), and the two facings' dot product, rounded half away from zero to six places, is at least 0.7071.

**`ResolveMelee`** (`0x800628A4`): a d100, which `AdjustRoll` (`0x80062594`, magic's) turns with Warrior: at or under min(Warrior, a fifth of the chance), a second d100 comes off it. A hit is the adjusted roll under the chance.

- **A hit** draws the damage, then a d100 for the weapon skill (`Combatant.GainSkillExperience`, `0x80062650`: at or under a tenth of (8 − skill)² for a skill under 6, else 5, the base trains a level; half the points on a miss). It shows and queues "%s attacks %s" (`0x24`) or, the roll adjusted, "%s scores a critical hit on %s" (`0x2C`), and queues "%s loses %d hit points" (`0x30`; `0x34` for 1).
- **A miss** draws the experience, shows "attacks" and queues "%s avoids the attack" (`0x20`).
- So a melee hit draws the roll, [the adjustment], the dice, [the weapon's spell], the experience. **A critical is only its line**: the second d100's bigger margin is its only effect.

**`MeleeDamage`** (`0x80062AE4`): (the weapon's dice + the Strength tier) d6 (`Combatant.StrengthTier`, `0x80062008`: the first of 4, 9, 17, 24, 28, 32, 36, 39 at `0x800E0C30` the modified Strength is at or under, else 8); plus the margin's step (`SkillCheckStep`, `0x800DA348`) and the attacker's base Level; less protection (`ProtectionVsAttack`, `0x8005F71C`: `TotalProtection`, `0x8005F570`, the sheet's, body armor's and a fifth of Warrior, 0 if under 1, plus the shield's unless from behind, a byte); plus Thief × 2 from behind; at least 1. Then **`ApplyResistance`** (`0x80062704`): the product of every resistance of the target's own and its gear's that meets the weapon's element (`ResistanceApplies`, `0x80061A30`: the element, Physical also Cutting and Smashing, Magic every magical one), truncated, at least 1 unless one is 0; a weakness over 1 makes an enemy's morale check due. Then the weapon's spell's damage (`Combatant.WeaponSpellProc`, `0x800627D0`), cast as any spell, so its roll's step is kept as the attacker's cast margin (`+0x3C`, `PrepareCast`'s `0x80064184`) until the turn ends; nothing reads it. The sheet's own damage byte (`CharExp+3`) and the entity's damage aren't read.

**Ranged** (`Combat.RangedChance`, `0x80062F50`): the attacker's modified Intelligence and Dexterity, base Level, the hit, 6 × the skill and 2 × Warrior; less (distance − 5) past 6; less the target's base Level, and unless it's held, its 2 × Dexterity and shield defence; 20 from behind (no Thief); × 1.2 against a target that hasn't moved or acted (`+0x22` 0), × 1.15 against one with no Stamina, × (h × 0.05 + 1), × 0.9 with no Stamina of its own, × (1 − the rain's intensity × 0.3), × 0.7 at night, × 0.8 against one that has moved; the aspect, the Troubadour, at least 5. `ResolveRanged` (`0x80063324`) is `ResolveMelee` with no Strength dice and no blow from behind in the damage (so the shield's protection always counts), the experience after the lines, and "%s misses %s" (`0x38`). No ammunition is spent. `Combat.WeatherPenalty` (`0x80062D78`) is `ThrowChance`'s, not this; `Combatant.HeightModifier` (`0x80062E0C`) has no caller.

**The action's states** (ticks are the frame's delta; the action timer is `+0x52CC`):

- **State 2** (`Combat.StateAction`, `0x80021774`) waits for the blow (`Combat.StepActionTimer`, `0x80021708`: the action timer, counting every frame's ticks, at 30 or more **and** the attacker's body's `+0x18` 0, a signed halfword). Then an arrow or thrown weapon flies (below), or the blow lands: with damage, `Combat.ApplyHit` (`0x80021930`) takes it through `Character.TakeDamage`, sets the target's request 7 and shows the number over its head (`Combat.ShowDamage`, `0x80021294`); with none, an opponent dodges (request 8) and an ally is helped (10, with healing's number); a dead target falls (`PlayDeathAnimation`, request 9 at once). Then state 4, with the queued line shown (`FlushQueuedLog`). The attacker's swing plays on meanwhile.
- **The strike** is when `+0x18` goes to 0, not the swing's end. `Bodies.Process` (`0x80012784`) sets `+0x18` to the body's request (`+0x14`) as the actor enters a state, and also (`0x80013108`–`0x800132D0`), for a body playing an attack (`+0x18` 12 to 18), on the tick its frame before the step is `(u16)(int)(length × share)` in single precision: the share is the entity's (`EntityBody.Strike`, `0x8006C7FC`: its row of the model table, `CodeTable.EntityModels` `+0xC`, 0.2 to 0.67, or 0.4 at `0x800D2CF8` without one), or 0.4 for a bow's or a thrown weapon's requests 14 and 15 (`EntityBody.ShotStrike`, `0x8006C884`, `0x800D2CFC`). The request is 0 by then (`Combat.AfterFrame` let it go after its first frame), so the blow lands at the next check. The attacks are each a single Borg7 state with one branch, any request back to idle, so nothing else is keyed to them. Counted from the request's frame, the target reacts at the first frame at or past `max(30, H + 2)` ticks, H the strike frame; at 2 ticks a frame Alaron's Short Sword lands at 32 (state 39, 71 ticks, 0.42, H 29), a rat's bite at 66 (279 ticks, 0.23, H 64) and a goblin's Sabre at 82, where the swings end at 72 to 280. Checkpoint 10's rat is at frame 51 of its 279 with `+0x18` still 16, before its strike at 64. An entity whose actor has no branch for its weapon's request (the Goblin Sergeant `0x0216`'s Short Bow, 14) never takes it, `+0x18` stays 0, and the blow comes at the 30 ticks.
- **State 4** (`Combat.StateResult`, `0x80021F30`): `Combat.RemoveFallen` (`0x80021D2C`) waits for the target's body's `+0x18` to be 0 and 60 ticks (a rat's fall is 239), then frees a dead one's body (`Combat.FreeBody`, `0x80021C6C`: its effects and potions off, its numbers gone, its portrait skulled, the body's fade started, `Combat.Bodies[slot]` emptied, the record kept), gives the camera back to the attacker and deselects the target. With no target left, the turn ends: the next begins as the body starts to fade, and nothing waits for it.
- **The one-shot requests**: after every frame `Combat.AfterFrame` (`0x80023360`) zeroes each body's request but 0–3, `0x14`–`0x16` and `0x19`, so a request combat makes is asked for through every tick of its frame (two at 30 fps), and `Bodies.Process` copies the request to `+0x18` whenever the actor enters a state (and at an attack's strike, above), so `+0x18` goes back to 0 when the reaction ends and the actor idles. A dead body (`+0x18` 9, its request no longer 9) holds its last frame (`+0x77C`), where `+0x18` takes 0. That's `Bodies.Process`' rule for every body, which cut-scenes' actors play by too ([scripts](scripts.md#actors)).

**`Combatant.Death`** (`0x80062080`): the immobilising effects come off, its footprint leaves the grid, the active counts fall (`+0x02`, and `+0x04` or `+0x06`), Sholeh's death sets flag 622, a party member stops performing, and the first enemy's death sets `+0x08`. It doesn't set flag 6 or free the body: a dead combatant is known by its hit points. A death from the effects at a round's end (`Entity.ShowAgeResult`, `0x8007138C`) shows the number, then `Death` and `FreeBody` at once: no fall, no line, no wait, the body fading out standing as it was.

**A freed body's fade** (`Body.FadeOut`, `0x80014AD4`, which `Combat.FreeBody` calls for every body it frees and `Combatant.Leave`, doing the same work inline, for a fled one): body flag `0x100` and 120 ticks at `+0x708`. `Combat.Bodies[slot]` is emptied, but the body stays in the zone's bodies where it lay or stood, and `Bodies.Process` (`0x80012CA4`–`0x80012D40`) counts it down by the frame's ticks before the body moves: under 1, its alpha (`+0x70C`) and flags are cleared and it's freed (`FreePlayer`, `0x800146E0`); under 60 (`Body.FadeSpan`, `0x800CDB2C`), its alpha is `(u8)(left / 60 × 255)`. So it's drawn whole for the first second and fades to nothing over the next, linearly, by alpha alone; the body's alpha caps its distance's fade and its shadow's (`BodyShadow.DrawAlpha`, `0x800122C4`). While the flag is up its actor isn't stepped (`0x800130F0`), so a dead body keeps the last frame of its fall and a fled one the pose it fled in. It still pushes and is pushed as any body (the push skips only a body that's off or flagged `0x400`). A party member who dies is freed the same way, by the same `RemoveFallen` (it tests only `Character.IsDead`, `0x8006EA54`), and fades out as an enemy does; nothing keeps a dead member's body on the field. Alaron's keel-over in the Goblin Ambush isn't a death (he's left with some 45 hit points), so his body stays down at its fall's last frame. Checkpoint 06 holds rat 7 mid-fall in state 4 (`+0x18` 9, no fade, alpha 255); none catches a body fading.

**Arrows and thrown weapons** fly as the spells' cast scene (`Combat.CastScene`, `0x800DB0C8`, state 3). After the swing, `Combat.StartCastCamera` loads the arrow (Borg5 `0x348F`) for a bow, else the weapon's own model (`Combatant.LoadWeaponScene`, `0x80066CF8`), from the hand's locator (`SceneGetLocatorPos`, `0x8009ECD0`, of `+0x88`, as the body was last drawn; with no such locator nothing flies, and the blow lands all the same) to the target's middle (its feet plus half its height), or a flask's to the target body's centre (its sphere's, one radius above its feet). The held one is freed as it leaves. It goes in a straight line in 3D, its length L (`Combat.MissileLength`, `0x800DB0B0`), `v` a tick × the frame's ticks, raised by sin(travelled / L × π) × `arc`, with `f = muzzle + (L ≤ 40 ? L/40 × 4 − 2 : 2)`, `v = f > 10 ? 0.5 : f ≥ 1 ? f × 0.05 : 0.05`, `a = 10 − muzzle + (L ≤ 40 ? L/40 × 8 − 4 : 4)` and `arc = a > 10 ? 7 : a ≥ 1 ? a × 0.7 : 0.7`, the muzzle number by weapon (`Combatant.WeaponMuzzle`, `0x80066DD0`, the combat record's `missiles`). It's scaled as the attacker and turned along its way (`Combat.DrawCastScene`, `0x80021300`): rolled about its own X by its angle (`Combat.MissileAngle`, `0x800DB0C4`: the muzzle's turn, 90 for the Javelin, plus its spin a tick, a flask's 8), which `Scene.SetRotationRPY` (`0x8009DA48`) gives `guRotateRPYF` as the roll, then by `guAlignF` with no twist to the line's direction (`Combat.MissileStep`, `0x800E6870`), so its −Z points along the line and its Y as near up as the line allows: a flask tumbles end over end toward its target. In play (the user, 1.0 and 1.1) Brenna's flask leaves her hand at the top of her throw and arcs to the rat. It leaves at the throw's or the shot's strike (state 2's check, above), partway through the animation: a Goblin Poisoner's Poison Dart (request 15, state 9 of actor `0x302A`, 199 ticks, 0.4, H 79) at tick 82, not 200. The blow lands once it has arrived **and** the action timer, which `Combat.StateCast` (`0x80021B24`) counts from the launch through the flight, has reached 30 (`Combat.EndCast`, `0x800219D8`): on arrival for a flight of 30 ticks or more, a dart's of 5 or more units. The Goblin Ambush's darts are the four Goblin Poisoners' (entity `0x022A`, script `0x0365`). **`CombatAttackFx.Add` (`0x80089B80`) has no caller** in either build.

**The numbers over heads** (`CombatStatIndicator`, `0x8008A000`–`0x8008A8D4`): a pool of 16. Each is its number (a byte, 1–3 digits) put into a 64 × 16 texture from the digit textures (Borg1 22, 17, 21, 20, 15, 14, 19, 18, 13, 16 for 0–9, upside down), centred, at the body's X and Z and its head's height (half a unit higher for healing), and stays there. It's a billboard of 0.5 × 0.2 (healing 1.5 × 0.6), growing by s × scale across and s × 0.4 × scale up and rising s × 0.5 × scale, with s = sin(t / 120 × 90°), negative for healing, and scale its distance from the camera × 0.15; coloured (255, 255, 128) for damage and (128, 128, 255) for healing, its alpha `(u8)(base − (s8)(s × 255))` from 255 (0 for healing); gone at 120 ticks. Nothing is shown for a miss, a critical or a death.

They're drawn as the shadows are (`Plane.SetDrawState`, `0x8004C350`, with flags 9, then `Plane.Draw`, `0x8004C4A4`, from `CombatStatIndicator.Frame`), after the world and its bodies (`Combat.DrawFrame`, `0x80021564`, after `HandleZoneEngineFrame`). The state list it calls (`0x800DFCC0`) sets one cycle, `TEXEL0 × SHADE` for colour and alpha (`G_CC_MODULATERGBA`) and **bilinear filtering** (`G_SETOTHERMODE_H` `0xE3001201 00002000`, `G_TF_BILERP`); nothing on the numbers' path sets the filter again. The texture is IA8, 64 × 16, its intensity and alpha alike, with no mip levels (`G_TL_TILE`), S wrapped and T clamped (`Scene.SetTextureTiles` given `0x1000`). Flag 1 turns on the z-buffer and the pixel's depth (`0x200005`, `G_ZS_PIXEL`), with `G_RM_ZB_XLU_SURF` (`0x504A50`): blended, tested against what's drawn and not written, and without fog. `CombatNumbersView` draws them filtered linearly, Godot's stand-in for the RDP's three-point filter ([rendering](rendering.md#whats-left)), without mipmaps and clamped (the texture's first and last columns are always clear, so wrapping S changes nothing). It tests them against the depth as the original does, without writing it, so a body or the scenery in front of a number hides that part of it.

**The target marks** (`CombatTargetMarks.Draw`, `0x80089830`) aren't a cursor. Every frame, in every state, each combatant selected in set A (set B in states 10 and 11) has its body's ambient light set to a grey of |sin(n × 3°)|, n its ticks marked (`Body.SetTint(body, 1.0, f, f, f)`, `0x8001371C`, which takes the tint's level to 1 at the next step): a pulse from dark to full once a second, ending at once when it's deselected (`Body.ClearTint(body, 0.0)`, `0x80013774`). So the selected enemy pulses in state 1 as soon as one is in reach. It's the ambient, not the lights: the sun still lights it over the grey ([What spells look like](#what-spells-look-like)). The tint's level is 1 throughout (checkpoints 04–06: level 1, the ambient the pulse's grey), so the moon's cyan light on the body is at full, (0, 193, 193) in the rats' battle's morning (moon height 0.966 in checkpoints 01–11, `Bodies.SetLights`, `0x80013960`–`0x80013a6c`), and on the dark side of the pulse there's little else. Like every light the engine adds, it reaches only the first vertex of each pair the RSP loads, the others taking the near-black ambient alone ([rendering](rendering.md#bodies-light)), so the original's dark rat shows only a little green. The port lights the same vertices (importer 59); lighting them all made the dark side plainly teal.

**Reserves** (`Combat.SpawnReserves`, `0x8005D914`, at a round's end after the effects age; running it on 08 gives 09's cells). It refills **every** enemy slot whose combatant is dead or gone, or that's empty, from the party's size to `+0x01`, while the list has a next (`+0x07`):

- A reserve that flees as it arrives (`EnemyAI.ReserveFleesOnArrival`, [The AI](#the-ai)) is marked and skipped, its slot left empty, with the hold's line.
- The leader's slot taken sets `+0x0C`.
- The newcomer stands at `Combat.ChooseSpawn` (`0x8005D748`, through `SpawnPosition`: one draw for its direction, `Range(5, 7)` with collision byte 0, else `Range(1, 3)`; set 0, the enemies' side, the slot's letter, `a` + slot − party size), or if that cell is taken, or a body's centre is within its radius and the newcomer's, the first free and clear point of sets 0–4 in turn, its side's letters first (`0x8005D5B0`, `0x8005D474`).
- Its body, radius, field, portrait and action are made as `Combat.CreateBody` makes them, with flag `0x400`, and `+0x07` moves on. The counts aren't changed: `CountActive` finds the newcomers at the next turn's change. Checkpoint 09's newcomers walking is their own AI turn, not the spawn's.

**The random stream between checkpoints**: besides the battle's own draws, `Weather.DriftWind` (`0x8007BAA0`, from `Combat.AfterFrame` through `World.SetTerrain` and `World.Update`) draws 2 every drawn frame, plus 3 with chance 0.05 and 1 more with 0.05. It accounts for every draw from 04 to 05.

## The AI

Read from 1.0's code (`0x80056E10`–`0x8005C0C0`, `aiInfo.cpp` and `aiscores.cpp`) and checked by running the original's own functions on the checkpoints' RAM. The user's memory of play agrees on the casters: they put up their shields and other help first, again and again, and once one takes to its weapon it doesn't cast again (the Wight late in the game, whose turn to its weapon players are glad of).

**The record** (0x1C, `EnemyAI.Init`, `0x8005BA7C`; `EnemyAI.Free`, `0x8005BD90`):

| Offset | Holds |
| --- | --- |
| `+0x00` | the spare weapon: an item made from the entity's first weapon, only when its first and third are both set; what `EnemyAI.SwapWeapon` trades the held one for |
| `+0x04` | the type it fights as: 0 melee, 1 ranged, 2 caster, from the weapon and spells; `ChooseWeapon` makes it `+0x07` |
| `+0x05` | the target's slot, `0xFF` none |
| `+0x06` | morale, the entity record's (`+0x1B` in RAM): 5 for rats, 12 and up never flee; spells of kinds `0x19` and `0x2F` lower it until the effect ends, when `EffectRules.End` (`0x800707EC`) gives back what they took ([magic](magic.md)) |
| `+0x07` | the type its style wants this turn; unlike `+0x04`, `Execute` swaps weapons first |
| `+0x08` | the attack style, 0–10 (`EnemyAI.StyleTable`, `0x800E0B80`, a function every 8 bytes) |
| `+0x09` | flags: 1 fleeing, 2 a morale check due, 4 two more morale (nothing sets it), 8 the AI plays its turns (set by `Init`, tested by `TurnOrder.BeginTurn`), `0x10` hit by a weakness (never cleared) |
| `+0x0A`–`+0x11` | eight action slots, spell kinds or `0xFF`: the entity's first five spells in its record's order (its spellbook's places 0–4), its armor's, its shield's and its weapon's own spell (the one it's cast from, not the one it strikes with); a slot chosen becomes the entity's selected spell by `EnemyAI.SlotIndex` and `SlotKind` (`0x800E0B70`, `0x800E0B78`: source 1 with the place for 0–4, then 2, 3 and 4). No enemy has an armor's or shield's spell; Kitarak, Shamsuk, Lugash and Golnar have a weapon's |
| `+0x12`, `+0x13` | the path's next corner and its length |
| `+0x14` | the combatant |
| `+0x18` | a flight's turns left: 4 as it starts |

**The style** (`Init`): no weapon, 5; a melee weapon, 0, or 1 with a base Intelligence of 15 or more, or with any spell 6 (9 for the bosses, `EnemyAI.HasBossStyle`, `0x8005BA40`, a jump table at `0x800D24B0`: entity list places `0x57`–`0x59`, `0x5E`, `0x5F`, `0x7A`, `0xA7`–`0xA9`, `0xAB`, `0xAD`, `0xBA`, `0xBC`, the combat record's `BossStyles`); a ranged one, 2, or 3 clever, 4 if it strikes in melee too (`Weapon.AllowsMelee`), or with a spell 7, 8 (10 for the bosses). Rats, wolves, trolls, skeletons and Goblin `0x0215` are style 0; Goblin `0x022E` and Goblin Scout `0x024E` 2; Goblin Scout `0x0208`, the Bandit Woodsmen and the Goblin Poisoners 3.

**An enemy's weapon** (the entity's build in its enemy mode, `0x8006E2E8` through `0x8006E434`): the third weapon slot's if it can wield it, else the first's; the second is never read. Every entity with a third weapon can, so the first is the fallback only for those without. The goblin archers hold a bow with a sword as the spare.

**A turn** (`EnemyAI.Step`, `0x8005B314`, the first frame of state 8). An enemy decides once and walks once: one plan, at most one leg, then at most one action or a rest.

1. It reads its body (`Combatant.SyncFromBody`) and keeps where it starts.
2. Not fleeing, its style chooses (`EnemyAI.ChooseGoal`, `0x8005B144`; `EnemyAI.RunStyle`, `0x80059628`): the style fills `AiScores` and sorts it, and the first entry is the target (`+0x05`) and the goal cell. At the goal already, it acts (`Execute`). Fleeing, the goal is the nearest flee point (below).
3. **The path** (`EnemyAI.PlanPath`, `0x8005A974`; `ArenaGrid.FindPath`, `0x80068CD4`): both footprints are freed; from the start it steps to the free, unmarked, gentle neighbour (a rise under 3 half units, `ArenaGrid.IsGentle`) nearest the goal by the distance squared, the first of equals in the directions' order N to NW, marking each, until the goal or the grid's diagonal. It never searches: at a dead end it counts back without stepping back, so any pocket, a ring of bodies or a wall's corner between it and the goal, fails it. The grid is filled again with every living body that's still there (`ArenaGrid.RefillWithBodies`), and a path is cut to its corners (`TrimPath`, `0x80068784`, takes the loops out; `StraightenPath`, `0x8006894C`, keeps a run's last cell). With no path: walk straight at the target if it's within its bodies' radii and 2.25 (`EnemyAI.ApproachTarget`, `0x8005AB14`), else act from where it stands.
4. **The leg** (`EnemyAI.WalkPath`, `0x8005A0D8`): corner after corner, each queued for the body to run to (`SetPlayerMoveToQueue`, `0x800157C8`, a ring of 16) and the facing that way, until the path's end or a stop. A corner that's taken or too steep stops it at the first blocked cell of the straight line there (`EnemyAI.WalkIsClear`, `0x80059C94`, a Bresenham line), so a rat runs into its target's cell and the bodies' push holds it off. A corner past the field, measured from the turn's start, stops it where the line leaves the circle (`EnemyAI.ClipToCircle`, `0x80059A84`, whose quadratic has b where 2b belongs), rounded: an engaged enemy, of radius 1, moves a cell. The combatant stands on the leg's end at once, on the grid too, while its body runs; flag 3 is set for a leg of 3 or more. State 5, the stuck timer at 240. If no corner could be walked it only turns toward the first (`EnemyAI.FaceStep`) and approaches or acts.
5. **The walk** (state 5): **A skips it** (`Combat.InputMoving`, `0x80084F98`, on A's press): for the current combatant's body with a path (flag `0x10`), `Body.GiveUp` (`0x80015C28`) puts it at once at the last point queued (the ring's entry before `+0x254`, or with it spent, the goal it's heading for, `+0x260`), sets it down (`Body.SetDown(body, 0, 0, 0)`), faces it to `+0x28` if it was turning and clears the path, so the state's next step goes on as on arriving. Nothing between is tested, so a body that would have stuck on the way (another body's push, a wall's edge) is put at the leg's end all the same, where the combatant already stands on the grid. It asks only that the body walks a path, not whose side it's on: Sholeh's walks with an AI record skip too. No sound plays. Otherwise the body runs (stick 0.95, `Body.WalkStick`) to each point in turn, arriving within its scaled radius. A body that comes no nearer by 0.01 for 30 ticks, counted over the whole point, gives it up where it stands in combat (`Body.StepTowardGoal`, `0x800159C8`, which outside combat puts it at the goal); and every tick it moves under 0.03 counts the stuck timer down. With no point left, state 6 turns it the way it walked (`Combatant.FaceAndSettle`), and then, with `NextState` 8, `EnemyAI.FleeAdvance`: for an enemy not fleeing, `Execute`. The timer run out does the same from wherever it is.
6. **The action** (`EnemyAI.Execute`, `0x8005B594`): a weapon swap first if its style wants the other kind (`ChooseWeapon`, `0x8005A620`, which makes what it fights as, `+0x04`, what it wants, `+0x07`, and clears the selected spell's source, `ce+0x3D`; `SwapWeapon`, `0x8005A560`: "%s changes weapons", and the turn's spent resting); then (`EnemyAI.PrepareAction`, `0x8005B1D8`) Fireball's centre (`AimAreaSpell`, below) and both target sets from where it stands (`EnemyAI.PrepareTargetSets`, `0x8005B8F8`): for one that fights as a caster (`+0x04` 2) the spell's target first (`SelectSpellTarget`, `0x8005B878`: its target if set B has it selected, else B's cursor, set A emptied), then the weapon's; for any other the weapon's first (`SelectWeaponTarget`, `0x8005B7C8`: its target selected alone if set A has it, else whoever set A selected, set B emptied), then the spell's; and if it can act on that one (`EnemyAI.CanActOnTarget`, `0x8005B218`, which makes it the action's target, `+0x14`: a caster `CanCast` or `CanAttack`, the rest the other way round), it turns to it (`Combatant.FaceCombatant`, state 6) and attacks or casts through `Combatant.ExecuteAction` as the player does: state 6 attacks if set A has the target selected, else casts if set B has (nothing sets the AI's cast margin `+0x3C` first; `PrepareCast` rolls it). Otherwise it rests: state 24, 120 ticks (`Combat.EnterRest`), and the turn ends. So a caster whose weapon fallback has once won (styles 6 and 9 want melee, so `+0x04` becomes 0) is weapon-first from then on: with anyone in its weapon's reach it attacks, even when a spell scored best, as no fallback makes it a caster again.

**The styles** score with these: `ListOpponents` (`0x8005783C`, one entry per opponent in slot order: alive, able and on the other side); `ScoreByDistance` (`0x80058B90`, the grid's distance from the AI's cell, `ArenaGrid.Distance`, a square root truncated); `AreaDanger` (`0x80058A48`, 5 for each ally within the party's area danger `+0x12`, while the leader lives); `CollectAttackCells` (`0x80057908`, each free cell in its field from which set A has someone, with the nearest of those) and `CollectAttackCellsByReach` (`0x80057C30`, one cell per opponent, preferring cells no opponent's field reaches, then nearer); `ScoreAttackCells` (`0x80058C7C`, round each opponent the free cells from which set A has it: 25 its own cell, 20 the flank or back, `Combatant.IsFlanking`, 50 above it, up to 15 the more it's hurt, 10 if it holds a ranged weapon); `FarthestCell` (`0x800587BC`, the free cell in its field with the greatest summed distance from the opponents). The cell collectors try each cell by moving the combatant's place there and building set A, but `Combatant.IsWithinReach` reads both bodies again, so for melee reach only where its body stands counts: a clever melee fighter (style 1) far off finds no cell, and takes an opponent's own cell, the one the sort puts first.

| Style | Who | Chooses |
| --- | --- | --- |
| 0 | melee, Intelligence under 15 | the nearest opponent; its cell |
| 1, 4 | melee, clever; a weapon for near and far | each opponent's best cell (`ScoreAttackCells`), the best first |
| 2 | ranged, Intelligence under 15 | the nearest cell to attack from; with none, the nearest for the other kind of weapon, which it then wants; with none either, the nearest opponent |
| 3 | ranged, clever | with an opponent in reach, its best cell in melee, wanting melee; holding a melee weapon with none near, the farthest cell, wanting its bow; else the nearest cell to shoot from that no opponent's field reaches, or if all are reached the farthest; with none, style 0's |
| 5–10 | casters and bosses | their spells first (`EnemyAI.ChooseSpellOrAttack`, below), changing neither what they fight as nor what they want; with none that scores: 5 as 0, 6 its collected attack cells scored (or style 1), wanting melee, 7 as 3, 8 as 4, 9 as 6 over the opponents, 10 as 3 with the farthest cell as its fallback and the nearest order |

**The casters' spells** (`EnemyAI.ChooseSpellOrAttack`, `0x800590B0`; `ScoreSpellCells`, `0x800581C8`). Every action slot with a spell, in slot order, is scored from every free cell within the field (the square about its cell, Z outer and X inner, within `ArenaGrid.Distance` of the radius, free for its footprint with its own taken off, so its own cell counts): the combatant's place across the ground is moved there, the slot's spell selected and set B built for it there, and if B selects anyone and the spell has a value (`EnemyAI.SpellValue`, `0x80057498`, [magic](magic.md)), an entry of the cell, the slot + 1, B's cursor (the last it selected in slot order, or the combatant's last target or B's old cursor where `TargetSet.RestoreCursor` keeps it) and the score **(value + 10 × (selected − 1) + the spell's known level) & 0xFF** (the spellbook's level, or the item spell's, not the casting level). For Fireball (spell kind 8, and no other), the count is `EnemyAI.AreaCentre` (`0x80058008`): the area's centre (`Combat+0x18/+0x1C`) put at the mean place of the opponents, B built about it, and with anyone selected, +1 for each candidate of the other side and −1 for each of its own, itself included; a negative count wraps the byte, so a Fireball that would catch more of its own side than the other scores above everything. The list holds `(r² × 4 × 8) & 0xFFE0` entries, 32 for an engaged caster, and drops the rest. With a field of 0 (Pochanargat) only its own cell is scored (`ScoreSpellsInPlace`, `0x800585B0`). With any entry: sorted best first, the best's ties kept (`KeepBest`), each scored again by its distance (`ScoreByDistance` with the allies' area danger), and sorted nearest first: of the cells tied for the best spell, the nearest. `RunStyle` (`0x80059628`) then selects the entry's slot's spell. A slot the caster can't afford has no candidates (`AICanCast`, [Spells, potions and skills in a turn](#spells-potions-and-skills-in-a-turn)), so no entry; the flag `ScoreSpellCells` returns for it nothing reads.

**Buffing ahead** (the user's note in [engine-behaviour](../engine-behaviour.md#enemy-ai)) is the values: a spell for its own side is worth 51–85 (Darkness 85, Haste 73, Mirror 72, the `vs.` spells 71, the shields 61, the stat spells 51–56), a debuff or a hold 31–43 and a damage spell 11–22, and the count adds 10 a target more, so a Starlight Shield on the caster and an ally (61 + 10 + 5 = 76) beats Web of Starlight (48) and Lightning on three (36). A buff isn't cast at one already under it (`Casting`'s test of the target), so once its side has it, it attacks or debuffs. Every cell that reaches its allies scores the same, so it casts from where it stands. Checked by running 1.0's own code with casters laid over the checkpoints' rats.

**Fireball's aim** (`EnemyAI.AimAreaSpell`, `0x8005974C`, before the target sets, for kind 8 alone): of the cells of the arena within the spell's range byte × its casting level (3 × level) of the caster, Z outer and X inner, the first with the most candidates of the other side less its own, more than 0, becomes the centre; with none, the cell of `AreaCentre`'s mean. The blast's own reach about that centre is the casting level (`Combatant.CanCast`).

**The bosses** (`EnemyAI.HasBossStyle`, `0x8005BA40`, whose one caller is `EnemyAI.Init`) differ only in their styles' weapon fallbacks, 9 for 6 and 10 for 8; they score their spells as any caster. The 13: the six Bandit Bosses, the Chaos Major, Kitarak, the Lizard Man Boss, Pochanargat, Shamsuk, Lugash and the Wight.

**The sort** (`AiScores.Sort`, `0x8005BFC4`) is the game's own quicksort (`Quicksort.Sort`, `0x800B3978`, `quicksort.cpp`), not the C library's: three elements or two by comparisons, more by a pivot drawn at random and Hoare's partition. Its draws are on a stream of its own (`Quicksort.Seed`, `0x800E6B60`), 0 at boot, never seeded or saved, one draw for each partition of four or more, so a rat choosing among four draws once. Equal scores, common with distances truncated, fall in the order it draws. Nothing else in the AI's choice is random, and its turn draws nothing on the main stream but the action's own.

**Stuck, and resting for no visible reason** (the user's notes in [engine-behaviour](../engine-behaviour.md#enemy-ai)), all the original's:

- The planner sees the grid alone: a cell can be free and gentle there and still blocked for the body (a wall's edge, a narrow gap), or held by the push of another body. The body then comes no nearer, gives up after 30 ticks where it stands, and the enemy acts or rests from there.
- The combatant stands on its leg's end at once, so enemies planning later route round a place its body may never reach; every combatant reads its body again as the next turn begins.
- A rest, 120 ticks with no line: the greedy path fails (a ring of the party and its own allies round the target, anything concave), and the target isn't in reach where it stands; the first corner can't be walked; after the leg nothing is in reach (cut short by the field, the give-up or the timer, or an engaged enemy's single cell); a weapon swap; a flight's leg.

**Morale** (`EnemyAI.CheckFlee`, `0x800572AC`, as an AI's turn begins, `TurnOrder.BeginTurn`): every AI combatant but the leader while it lives is asked; with morale under 12 and a check called for (`EnemyAI.MayCheckMorale`, `0x8005722C`: a check due, or no Stamina, or not already fleeing and no more than half the enemies that began able), the leader's morale is worked out first while it lives (`+0x11`), then its own (`EnemyAI.Morale`, `0x80056FA8`, which clears the check due), against 2d6 on the main stream: rolled over, it flees (`EnemyAI.StartFleeing`, `0x8005B9E4`: four turns, unless it's engaged or the arena has no flee points), otherwise it stops fleeing. Its morale, from 2 to 11:

| Term | |
| --- | --- |
| its record's | `+0x06` |
| aspect against the time (Lunar by day, Solar at night) | −1 |
| a weakness has hit it (flag `0x10`, set with the check due by `ApplyResistance`) | −2 |
| no Stamina | −1 |
| strictly fewer than half the enemies that began able | −1 |
| a harmful effect on it | −1 |
| fewer than half the party able | +2 |
| its target has no Stamina, unless its selected spell, whether it casts this turn or not, is one for its own side (`Combatant.IsFriendlySpell`, `0x80061008`: target type Party) | +3 |
| flag 4 (nothing sets it) | +2 |
| its own check: the leader gone or unable | −4 |
| its own check: the leader's morale 8–10, 11 | +1, +2 |

**Fleeing** (`EnemyAI.BeginFleeWalk`, `0x8005B038`): each of its turns says "%s flees" and heads for the nearest flee point (`EnemyAI.NearestFleePoint`, `0x8005AE3C`, the last of equals), as any walk: one leg, bounded by its field. Within 1.5 of the point it leaves at once. After the leg (`EnemyAI.FleeAdvance`, `0x8005B434`) its turns count down, and it leaves on the last, within 1.5 of a flee point, or if it hasn't got a unit from where its turn began; then it rests. With no path, it walks straight to a flee point within 2.25 (`EnemyAI.FleeStep`, `0x8005AA3C`). With no flee point at all it stops fleeing and chooses as any other. **`Combatant.Leave`** (`0x80061480`): it leaves the grid, flag 6 (gone), the counts of those able fall, its effects and potions come off, its body fades out over 120 ticks (`Body.FadeOut`, `0x80014AD4`), `Combat.Bodies` is emptied at once, and its portrait is marked fled. It isn't dead: the kill flags aren't touched, and it still pays its experience and chest.

**Reserves that flee as they arrive** (`EnemyAI.ReserveFleesOnArrival`, `0x80056E18`, inside `Combat.SpawnReserves` as a dead or gone combatant's slot is to be refilled): only where there are flee points, with morale under 12, and while **more** than half the enemies that began are still able; its record's morale, less 1 for its aspect (any but Solar counting as Lunar), 4 with the leader gone or unable, and the leader's morale's say, from 2 to 11, against 2d6. Fleeing, it's passed over (`+0x07` moves on), its small portrait marked (`CombatGui.MarkReserveFled`), its slot left as it was until the next round, and `+0x543C` set: the next turn's change shows "Enemy reinforcements flee" and the whole battle holds 60 ticks (`Combat.HoldForMessage`, `0x80022AEC`). `Combat.SkipFleeingReserves` has no caller.

**Sholeh** with an AI record plays her turns the same way; on the party's side she never counts as fleeing.

## Spells, potions and skills in a turn

Read from 1.0's code and checked by running the original's own functions on checkpoints 05 and 07 and against 08.

**The held menus** (`CombatMenu`, `0x80087C60`–`0x80089780`). `Combat.Controls` gives each poll's event to `CombatMenu.Input` (`0x80087C8C`) before the state's own: in states 1, 9, 10, 11, 18 and 25, a C-up press opens C-up's menu (`CombatMenu.OpenItems`, `0x80087F2C`, state 23) and a C-down press C-down's (`OpenSpells`, `0x80088028`, state 22), C-up winning a poll that has both. Opening puts an aim away (`Combat.CancelToTurn`, `0x80083C2C`: `ReturnToTurn`, and `RevertAction` from 9) and stands the body. The menu is a `ChoicePopup` that isn't in the widget manager, so it comes and goes on the frame, with no fade:

- **Moving**: the stick's or the D-pad's up and down move the cursor a row, wrapping, held repeating after 30 polls and then every 5 (`StickRepeat`, `0x800AD708`). A, B, Z, L, R, Start and the C buttons do nothing.
- **Choosing**: letting the button go (`CombatMenu.Close`, `0x80088118`) sets state 1 and frees the menu, whose destructor calls the cursor's row's callback (`DestroySpellsMenu` `0x80088F90`, `DestroyItemsMenu` `0x800895A0`), so the callback's state wins. The row is remembered by party slot (`CombatMenu.SpellCursors` `0x800E3180`, `ItemCursors` `0x800E3190`, reset at the battle's start) and the cursor starts there next time, clamped to the list.
- **C-down's rows** (`CombatMenu.BuildSpellsMenu`, `0x80088B58`): Lay On Hands while modified Healer isn't 0 and modified Stamina is at least max(1, 11 − Healer) (`Entity.CanLayOnHands`, `0x80071ED0`); Heal With Herbs with a Herb in the party's inventory and Stamina at least max(1, 5 − Healer) (`CanHealWithHerbs`, `0x80071F38`); Perform while modified Troubadour isn't 0; then the spells known, sorted by name with `strcmp` (so the `vs.` spells, lower case, come after the rest), each listed if its reagent is in the party's inventory or it needs none, and not Photosynthesis at night. Nothing else is tested: a spell out of reach, too dear or for the field is listed and fails later. The skills are blue (0, 128, 225, 225) with the Healer's cross `0x0185` or the lute `0x018C`; the spells red (225, 80, 80, 225) with their school's icon (`Spell.SchoolIcons`, `0x800DEFC0`: Chaos `0x01A9`, Elemental `0x01A5`, Naming `0x01A6`, Necromancy `0x01A7`, Star `0x01A8`, none for the unschooled). No level, cost or count shows.
- **C-up's rows** (`BuildItemsMenu`, `0x800891B4`, from `ListPotions`, `0x80088190`): one row a kind of potion the party holds, in the kinds' order, that `Potions.CanDrink` allows now (never a flask or Stealth: `ListPotions` skips kinds below 4 and kind 16; the port lists the potions whose record has `DrinkInBattle`, in the records' order, [magic](magic.md#potions-and-flasks)), green (0, 200, 0, 225) with the flask `0x35E5`; then the weapon's, shield's, body armor's and gear slots' spells with charges left (`CombatMenu.HasCharges`, `0x800885E0`), yellow (200, 200, 0, 225) with the item's own image.
- **Empty**, a message instead: "No spells or skills available" or "No potions or item spells available" (code strings), which releasing closes.
- **The look** ([ui](ui.md#the-held-menus), matched to the user's captures): the conversation box's feathered black panel round a list 120 wide at x 99, as tall as its rows up to 95 (55 without the Expansion Pak) and centred on y 120; each row its icon at its left and its text after it, at the menu's icon width + 5 (10 for C-down's, 16 for C-up's) and half that width less half the text's height down, with 3 under every row, so C-down's are 14 apart and C-up's 19; the cursor's row pulsing from (100, 100, 100, 100) toward its colour over 20 ticks and back (`WidgetPulseMenu.Draw`, `0x8002809C`), with no box; the arrows `0x38D0` and `0x38CF` 8 left of the list, fading in while there's more above or below; the list scrolling 10 pixels a tick. Checked: the rows of every member at checkpoint 07.

| Row | Sets | Then |

| a spell, an item's spell | the entity's selected spell (`+0x3D` the source: 1 known, 2 armor, 3 shield, 4 weapon, 5 gear; `+0x3E` the place or slot) | `Combat.BeginSpellTargeting` (`0x80083ECC`): a placed area (the spell's `unk1E` bit `0x10`) state 11, else state 10 with `TargetSet.BeginSpell` |

**The selected spell** persists: `Combatant.Init` (`0x8005EAE0`) selects the first spell a combatant knows as each is made, and a menu's choice changes it. `Combat.EndTurn` puts the cast's margin (`+0x3C`) to `0xFF` but keeps the choice; a refusal for the reagent, the Stamina or an item's charges (`Combatant.FailSpell`, `0x800636A4`), a spent scroll or wand and an equipment change with a spell (`Entity.ApplyItem`) clear it. Set B is built for it at every turn's start and as the combatant moves, so its reach tints the portraits red whether or not a menu opens.

**Target set B** (`TargetSet.Rebuild` in mode 1; `FindSpellTargets`, `0x800693C4`): every combatant `Combatant.CanCast` (`0x80060C38`) allows, and as many may be chosen as `SpellTargetCount` (`0x80060818`) gives: every combatant in play for an All spell (then every candidate), (level + 1) >> 1 for a ByLevel one, else one. `CanCast`:

1. Never by or at the Shadow (the caster's and the target's slots, `+0x20`, against `Combat.ShadowSlot`, `0x800D94CC`, at `0x80060C70`–`0x80060C88`; `Combat.CreateBody` sets it for place `0xAC`, compared at `0x8005C528`); `SpellCanTarget` (`0x80060988`): alive, not gone, on the caster's side for a Party spell and the other for an Enemy one (Area and All either, so Fireball takes the party too), not under the spell already, its requirement met, and `SpellKindAllowsTarget` (`0x8006088C`, the plugin's filter: the Elementals for Control Elemental and Banishing, no Chaos for Charming, the Marquis, the Zombies); an AI's own tests (`AICanCast`: the cost, a charge, no requirement, the time).
2. Teleportation and a Self spell take the caster alone.
3. Its reach: the effective level × the spell's range byte, from the caster's place, to the target's body, its scaled radius added (`InSpellRange`, `0x80060B60`); a placed area's is the level alone, from the placed point (`Combat+0x18/+0x1C`). Sense Aura has none.
4. Its line: `WalkClear` from the caster's (or the point's) cell, or the same cell, or `HasSight` from 2.0 above the floor under that cell (`0x800D28A0`, a sphere of 0.5 swept from 50 to −10) to the target's head, only the target's body excluded.

`Rebuild` selects in slot order. A menu's choice calls `TargetSet.BeginSpell` (`0x80069574`) instead: a spell of one target orders the candidates by angle as an attack does and starts on the last target if it's one, else the first of that order (the camera on the first); one of several selects them all if they're fewer than it takes, else the nearest to the caster's body (`SelectNearest`, `0x80069D90`, a later equal first), and the player chooses nothing. **Checked**: 07's set B for Rheda's Endurance (ByLevel, level 4) is the four members as candidates with her and Alaron, the two nearest, selected; and every member's spells give the candidates 1.0's `BeginSpell` gives.

**State 10** (`Combat.InputSpellTarget`, `0x800844BC`): Start pauses back to state 1; B, Z or L put it away; left steps a single target's cursor +1 and right −1, wrapping (`TargetSet.StepSpellOne`, `0x800696D4`), the camera to it and the caster's body turning to it (`Combat.AimAtCursor`); A is `Combat.ConfirmSpellTarget` (`0x80083F58`): set A emptied, set B's candidates cleared, the **highest** selected slot the first target (none: back to the turn), the camera to the caster, the margin 0, and the caster turns to it (state 6) or, casting at itself, state 6 at once.

**State 11** (`Combat.InputAreaTarget`, `0x80084964`), entered with the centre at the caster's place: the stick alone (not the D-pad) moves it 0.8 a frame, as state 18's cursor, up being the camera's way (`Combat.MoveAreaCursor`, `0x8008465C`), on the grid and within the range × the level of the caster's body, and set B is built again about it; state 11's camera is 8 and 16 about the centre. A is `ConfirmAreaTarget` (`0x80084184`), as state 10's, but Teleportation's point must be clear (`Combat.SpotIsClear`, `0x8005D474`: no living body's centre within its radius and the caster's), or nothing happens. `Entity.Teleport` (`0x80071978`) reads the point itself.

**The marker** (`Combat.DrawTargetCounts`, `0x80021448`, every frame) draws one translucent cylinder, scene `0x0797`, at the focus, set on the floor by a sphere of 1 swept down, scaled (r + 0.2, 2, r + 0.2) at the scene colours' alpha 64 (`CombatSpellFx.DrawNumber`, `0x8008ABD8`): red with r the reach about the caster in state 10, red with r the level about the point in 11 (1 for Teleportation), green with r 1 at a flask's aim in 18. It draws no numbers.

**The cast** (`Combatant.ExecuteAction`'s spell branch and `Combatant.CastCurrentSpell`, `0x80065C08`), a target at a time: set A's selection cleared; `CastSpell` at the target, the first preparing it and the rest sharing its roll, reagent and cost (the acted flag); a damage of 0 shows "%s casts %s" and queues "resists"; the caster's body plays request 5 and `CombatSpellFx.Start` (`0x8008C43C`) its visual, even for a refusal; then as an attack, `CheckDeath`, the damage on the target, the glide and state 2. State 2 waits for the caster's request 5 to end and 30 ticks, then the target is hit (request 7 and the number), or a same-side one helped (10) and an opponent dodges (8); state 4's `RemoveFallen` takes the target off both sets and, with more selected, turns the caster to the **first** selected by slot (state 6), until none is left and the turn ends. **A spell never goes through state 3**, which only arrows, thrown weapons and flasks take. A cast whose margin is below 0 (refused or failed) casts at no more targets for a player. The lines: "%s casts %s" shown, "%s cast on %s" queued and flushed at state 2's end; the failures shown and queued; a requirement's refusal "%s" with the Common strings' lines 258–270 (`Spell.CastMessages`, `0x800E2C00`, a pointer the string loader sets). **Checked**: replaying 07's A gives 08's state 2, target, margin 4, acted flag, lines and two draws, then Alaron with no draw.

**Potions and flasks** (`Combatant.ThrowFlask`, `0x80065600`, action 3):

- **A potion** is drunk (`Combatant.DrinkPotion`, `0x80064C84`, [magic](magic.md#potions-and-flasks)): a heal says what it gained (shown and queued) or that it failed, Stamina that it's full, the rest that it took; no number shows. The body plays request 5, one is used up and the action goes back.
- **A flask in hand** is action 3 with the kind and `+0x8A`; it stays in the party's inventory. It's taken in hand from the pause menu's Party tab (below), which ends the turn and stows the weapon (`Party.StowHeldItem`, `0x800763B0`, at the turn's end): the member is left unarmed. Each turn's start lets it go if the party has none left.
- **Aiming** is state 18 with set A: the other side, any distance (`Combatant.WeaponReach` is 400).
- **The throw**: `ThrowChance` (`0x80064EFC`): the thrower's modified Intelligence and Dexterity, base Level, 6 × Thrown, 2 × Warrior and 40, less half the target's shield defence, its modified Dexterity and base Level; less (distance − 5) past 6; 20 from behind; +10 at a target with no Stamina, −20 at one that has moved or acted, −25 having moved; the night's −30 and fog's −10 or a storm's −20 with the distance again (`Combat.WeatherPenalty`, `0x80062D78`); the aspect and the Troubadour; at least 5. A d100 that Warrior turns. A hit draws 4d6, 8d6 and 2d6 always and takes its own (`FlaskDamage`, `0x80065270`; Sleep Gas 15), shows and queues "%s attacks %s", keeps the damage on the thrower (`+0x29`) and the target's cell (`Combat+0x5444`), and trains Thrown on a d100; a miss queues "%s misses" on half the training. Either way request 15 and one used up (`ConsumeFlask`, `0x80064AB0`, which puts the action back): the next of the stack stays in hand, and **the last empties the hand at once, so it never flies or bursts**: its target dodges. The port fixes this, the user's choice ([Where the port differs](#where-the-port-differs)).
- **The flight** is an arrow's (state 3), scene `0x34C5` to the target's feet, the muzzle number 4 and a spin of 8 a tick.
- **The blast** (`Combat.EndCast` → `Combatant.FlaskExplosion`, `0x800652F8`) about the landing cell, its squared distance **kept in a byte** and its numbers shown at once, is [magic](magic.md#potions-and-flasks)'s; the target's loss is queued and its death checked. Then `EndCast` lands the target's share as a blow: **the target takes it twice**, and the number and the line show it once. **Ran** at 05: a Fire flask of 10 takes a rat from 31 to 21, then 11. **Seen** by the user in 1.0 and 1.1 alike: Brenna's Fire flask showed 15 over a rat and "loses 15 hit points", and left it all but dead. The port takes both as one blow ([Where the port differs](#where-the-port-differs)).

**The Troubadour** (state 25, `Combat.InputTroubadour` `0x8008508C`: no text, set A holding the caster; A is `Combatant.StartTroubadour`, `0x800662F4`): with a performance already going in the battle, "%s is already performing" and the turn goes on; with no Stamina, "%s is too weak to perform"; else (Troubadour × 5 + Intelligence) × 2 against a d100: made, the bonus (`Combat+0x13`) is the margin's step, at least 1, 3 Stamina go, "%s performs" and the notes over the performer's head ([What the bodies hold](#what-the-bodies-hold)); failed, "%s fails to perform". Then request 5 and state 26, 120 ticks, and the turn ends. The skill trains on a d100 at or under a tenth of (8 − skill)² (8 from 6), halved on a failure (`GainSmallExperience`, `0x8006620C`). The performer's turns say "%s continues to perform", and it pays a Stamina point each round's end. A performance ends as it acts, changes weapon or action, takes a potion or healing in hand, is engaged or dies, or with no Stamina at a round's end (`StopPerforming`, `0x80066100`, which takes the bonus back).

**The Healer** (`Combatant.ResolveHealer`, `0x8006591C`): set A's healing candidates (`CanAttack`'s branch): the caster's side, hurt, within melee reach and sight; Lay On Hands never the caster, Heal With Herbs the caster with no test. The Party tab's own rules: Lay On Hands with Stamina over 2, for 3, heals Healer × 2 + 5; Heal With Herbs takes a Herb first, then for max(1, 5 − Healer) Stamina rolls a d100 under Intelligence × 4 + Healer × 11 and heals 4 × the step. Healed: request 5, "%s heals %s" shown and queued, "gains %d hit points" queued, and the healing number (`+0x2A`) after the target's helped request; else "%s fails to perform healing". No skill experience.

**Sense Aura** (`Entity.SenseAura`, `0x80070070`) puts up the Party tab's message box with code strings by the cast's level: the target's name; from 1 "Leader" or "Follower"; from 3 "%d Total Hitpoints"; from 5 "Level %lu"; from 7 its resistances, "Immune to %s" at 0 or less, "Resistant to %s" under 2.0, else "Vulnerable to %s"; from 9 "Total Armor Protection %d". It holds state 4 from ending the turn; any press closes it and ends the turn at once (`Combat.DismissPopup`, `0x80083E30`). **Detect Moon Phase and Detect Sun Phase** only flag trek's sundial, which combat neither draws nor has: in 1.0 the write goes through a null pointer.

**Escape** (`Combatant.Leave` on each target while the party can flee) takes a member off the field as a fleeing enemy goes; its body gone, state 2 waits for it for ever, a softlock (by the code and 1.0's own functions run; Escape is reached only by cheating: Ardra, who knows it, never fights, and its scroll isn't in the game). The port fixes it ([Where the port differs](#where-the-port-differs)).

**The pause menu's Party tab** in a battle (`PartyMenu.InventoryA`, `0x80035FA0`, by `PauseMenu.Member`): only the member whose turn it is may change anything (Common lines 489, 490 say so); a weapon equipped (`Party.EquipWeapon`, `0x800758CC`, then `Combatant.AfterEquipChange`, `0x800610C0`: performing stopped, healing put away, the weapon's action, moved) or a flask taken in hand (`Party.EquipFlaskInCombat`, `0x800753F0`) ends the turn as the menu closes (state 19, `Combat.StateEndTurn`); a flask in hand shows in the silhouette's weapon slot, crossfading as it's taken (`DollEquipmentMenu::GetEntityItemId`'s weapon slot, `0x8003E66C`, gives the Fire Flask's `0x1000` while the member's combatant, found by `PartyMenu.CombatantOfEntity` `0x8003E5DC`, has action 3; the port's `CombatPause.Held` gives the one held, the same icon in the base game), though the weapon stays worn until the turn's end stows it; a drinkable potion is refused for C-up (line 488); a scroll goes on into a gear slot, up to three, with no turn spent, which puts its spell on C-up; a weapon taken off leaves the member unarmed with no turn spent; body armor and a shield can't come off ("You cannot equip that item in combat!").

## What spells look like

Read from 1.0's code (`combatspellvisuals.cpp`, `0x8008AD60`–`0x8008D1DC`; the debug build names `ProcessSpellVisuals` and the file), with its pools checked in checkpoints 08–12 and `Start` run on 07. There are **no status icons**: `combatstatindicator.cpp` is the numbers alone. What players remember as icons cycling over heads, "brief, then a long gap", is the lasting scenes' turns below. The six one-line functions at `0x8008AA20`–`0x8008AA84` are this module's entry points, not the stat indicator's.

**What each spell and potion shows** is data, on the spell and potion records' `visuals` and the magic record's `refused` and `resisted` ([hardcoded-content](../hardcoded-content.md)), from five `switch`es on the kind with jump tables, alike in all three ROMs: the caster's actor (`CombatSpellFx.CasterActor`, `0x8008CB40`), the target's (`TargetActor`, `0x8008CCE0`), whether the target's stands at the head (`TargetAtHead`, `0x8008CCA8`: the charms, the controls, Debilitation, Stupidity, Weakness, Exhaustion, Clumsiness and Crushing Death), the lasting scene (`AuraScene`, `0x8008CE78`), and a potion's actor and lasting scene (`PotionActor`, `0x8008D038`; `PotionAura`, `0x8008D0FC`: Acid, Strength, Dexterity, Defence). Each actor asks for a memory size, and is skipped when the heap's largest block is smaller, which with the Expansion Pak's 4 MB free never happens. Detecting Traps, Poison, the two Detects and Stealth show nothing; Banishing's target plays Escape's actor; a refused cast plays actor `0x1CAA` at its caster and a resisted one `0x37F1` at its target, whatever the spell (`AddVisual`, `0x8008B8D8`, `0x8008B8E0`).

**A failed cast is a refused one.** `ResolveCastRoll` (`0x80063DF4`) returns 0 for a roll at or over the chance, after "%s fails to cast the spell" (`Combatant.LogCastFailed`, `0x800637C0`, shown and queued) and the reagent given back; `AttemptCast` (`0x80063F7C`) and `PrepareCast` (`0x8006406C`) pass the 0 on, and `CastSpell` (`0x800648CC`) returns `0xFFFE` for it, as for a spell unavailable, a requirement unmet, a reagent missing or Stamina short. `CastCurrentSpell` (`0x80065C08`) turns `0xFFFE` into −2 for `Start`, so every one of them plays actor `0x1CAA` at the caster, with the caster's request 5 and the spell's own sound (`Player.SetCastSound` comes first), and no glow, no dimming and no lasting scene. State 2 then plays the target's helped request (10) for one on the caster's side or its dodge (8) for an opponent, as for a cast that did nothing (`Combat.StateAction`, `0x80021774`, on a damage of 0). Actor `0x1CAA` is particles alone: its scene (`0x1CA2`) has no models, and request 5 takes it to state 6 (99 ticks), which starts three emitters at its locator 4, at the caster's feet. Each puts up a burst of 12 after 0, 15 or 30 ticks and then one every 3 ticks for 38 to 46, over about a second and a half; they drift up, swell and fade from orange, yellow and pale blue to violet, teal and purple: the puff of coloured smoke players remember as the spell fizzling. The resisted cast's `0x37F1` (scene `0x37E9`) is the same at the target, its puffs falling and sliding sideways, green and yellow fading to amber and lilac.

**Starting** (`CombatSpellFx.Start`, `0x8008C43C`, from `CastCurrentSpell` for each target, after `Player.SetCastSound`): a cast entry in pool A (64, `0x800E3218`, whose index is the handle), a body entry in pool C (16, the original's "players", `0x800E3220`) for the caster and the target, and in pool B (128, `0x800E321C`) the visuals: a refused cast (result −2) the refused actor at the caster; a resisted one (−1) the resisted actor at the target; any other, damage 0 included, the caster's and target's actors and the target's lasting scene, which joins the turns (`QueueAura`, `0x8008B498`); then **the sky dims** to half over 30 ticks for 150 and back over 30 (`DimSky`, `0x8008AECC`; `Sky.FadeBrightness`, `0x8001DE88`, the brightness at `0x800D9518` that multiplies every sky colour and the backdrop), **both bodies glow** white (`GlowBody`, `0x8008B364`: `Body.SetTint(body, 30.0, 1, 1, 1)` for 150 ticks, then `ClearTint(body, 30.0)`, the body's fog off meanwhile), Darkness and Light ease the sky's time of day to midnight or noon over 60 ticks (`World.SetTimeOfDayGoal`, `0x8007C450`, an offset at `world+0x28` that only the sky, the sun and the moon read), and Wall of Bones, Frozen Doom and Web of Starlight hold their target's idle pose (`HoldBody`, `0x8008B3F0`, body `+0x70E`: `Bodies.Process` doesn't step an idle body's animation while it's asked for nothing). A potion drunk or a flask's blast on a body (`Combatant.AttachSpellVisual`, `0x80064B10`: a heal that took, the Stamina, Antidote and Restore potions, a lasting potion that took, each body a blast hurts or corrodes) sets its request to 5 and plays the potion's actor and lasting scene on it (`StartPotion`, `0x8008C664`): no glow, no dimming, no sound. `CastCurrentSpell` files the handle in the target's first record of the spell without one (`+0x14`), when the cast did damage or added an effect, and `AttachSpellVisual` in the first potion record of the kind without one (`+0x08`).

**An actor** stands at its owner's feet, the body's centre less its **unscaled** radius (`+0x64`), raised by the entity's height for one shown at the head, followed while its animation plays; it's never turned or scaled. It's asked for request 5 from its first frame, and ticked a tick at a time until its state's animation has run its length (119–401 ticks), then left where it was until its emitters' particles have all gone (`Particles.SceneHasEmitters`), when it's freed with its emitters stopped. Its scene's `+0x2A4` is the body it sits on and `+0x2A8` the other of its cast (`AttachScenes`, `0x8008BB08`: the caster's for the caster's actor, the target's for the target's; a potion's both the drinker), which its emitters' locator bits 7 and 8 name ([particles](../formats/particles.md)), so a Fireball's particles fly from the caster's locator 3 to the target's. It's tinted by the screen's fade (`Scene.SetTint(F, F, F, 255)`) and lit by its own scene's lights, under the combat camera. Nothing ends an actor early: a body that dies or leaves is only marked (`ClearForBody`, `0x8008C880`), and its visuals play on where they were.

**The lasting scenes take turns, one at a time across the whole battle** (the port's options can show each character's at once instead: [Where the port differs](#where-the-port-differs)) (`ProcessSpellVisuals`, `0x8008BCA0`; `NextAura`, `0x8008B510`): a translucent shell or ring at its body's locator 3 (the head), unturned and unscaled, loaded as its turn comes (5 frames after the last load), whose turn is a hump of alpha sin(t / 125 × 3.14) × 255 over 125 ticks (`AuraLength`, `0x800E3234`) times its material's own alpha; then the next body in pool C order that has any waiting takes its turn, or the same body, each body's in pool B order by a cursor of its own. **Every cast holds the turns back for 300 ticks** (`CastWindow`, `0x800E323C`): the playing hump's clock doesn't move, and the alpha's factor falls to 0 over 30 ticks and comes back over 30 after (`AuraFade`, `0x800E3230`, cos of a ramp). So nothing shows for 5 seconds after a cast, and with *n* lasting effects in the battle each shows for 125 ticks once every *n* × about 135: one buff alone pulses every 2.2 seconds; four buffed members each show 2 of every 9. There are no fixed slots. Only effects a cast or a potion in this battle made show: not gear's, nor those on before it began. **Checked**: 08's pools hold Rheda's cast with its lasting scene loaded and held at alpha 0 in the window; 09–12 show the turns passing between Rheda's and Alaron's scenes.

**Ending.** A record's end (`EffectRecord.FreeVisual`, `0x8007AB9C`, and the potion's `0x80079DB8`, from `Entity.RemoveEffect`, only in combat) calls `EndEffect` (`0x8008C7A4`): Darkness and Light ease the time back over 60 ticks, a hold lets its pose go, and the lasting scene is asked to stop, which it does once its turn's hump is over; the actors play on. A cast entry goes once its three visuals have (and for Darkness and Light, once their effect has), with its body entries' references (`Housekeeping`, `0x8008AF1C`). A second cast of an effect already on the target files no handle, so its lasting scene has no record to end it and takes turns until the battle's end. `Combat.Exit` frees everything (`CombatSpellFx.Free`, `0x8008C8E4`): every body's glow back over 30, poses let go, the time offset back in a tick. None of the pools is checked for room.

**No visual moves the camera or plays a sound.** The cast's sound is the caster's: `Player.SetCastSound` (`0x80065BFC`, only from `CastCurrentSpell`, so a refused cast too and never a potion) sets body `+0x72A` to 5 and `+0x72C` to the spell, and `AudioKeys.PlaySpellCast` (`0x800534BC`) plays the spell's sequence on the first tick the body's request is 5, as a body key does, then clears both. No combat file calls an audio function: a battle's sounds are the music, the weather and the bodies' keys, the weapons' among them.

**The bodies' light in a battle** is trek's (`HandleZoneEngineFrame`, `Bodies.SetLights`, [rendering](rendering.md#bodies-light)): the ambient, the sun, the moon, then the map's lights for the party's members, of which the Battle arenas have none. Only combat changes a body's tint (`+0x75C` level, `+0x760` rate, `+0x764` colour), which moves its ambient from half the sky's colour toward the tint's colour and scales the moon's cyan light: the target marks ([An attack](#an-attack)) and a cast's glow.

## What the bodies hold

In a battle each body holds its weapon and shield; in trek no body holds anything but what a script shows ([scripts](scripts.md), `ShowItem`), and nothing else in 1.0 writes the bodies' attachments. Read from 1.0's code and checked against the Combat checkpoints' bodies.

**A body's attachments** are three records of 12 bytes at body `+0x730`: a u32 Borg5 (0 for none), the scene once loaded (`+4`, 0 until the first draw loads it), and a u16 locator of the body's actor (`+8`). `AttachItemToPlayer` (`0x80014BA0`) frees the slot's old scene and sets the Borg5 and the slot's first locator (`Body.AttachmentDefaultLocators`, `0x800CDC0C`: slot 0 locator 0, the hand; slot 1 locator 2, the shield arm; slot 2 locator 3, the head); `ChangeAttachmentNode` (`0x80014C6C`) sets another; `FreeAttachmentFromPlayer` (`0x80014C2C`, `Body.FreeAttachment` `0x80014B04`) queues the scene to be freed (`Combat.FreeQueue`, `0x800D96B0`). Slot 0 is the weapon, the arrow or the flask; slot 1 the shield or a bow; slot 2 the Troubadour's notes. `FreePlayer` frees all three with the body (`Body.FreeAllAttachments`, `0x80014B48`).

**What goes in them** is `Combatant.EquipVisuals` (`0x80066AEC`): slots 1 and 0 freed, the locators set to 0 and 2 (`+0x88`, `+0x89`), then:

- **The arm** holds the shield (`Combatant.ShieldModel`, `0x80066844`: the entity's armor slot 1, its model by `ItemTables.ShieldModels`), unless the entity's record has the shield skill 0xFF (`Combatant.CannotUseShield`, `0x80066C18`: Brenna, Donovan, Godric, Keelin, Niesen and Sholeh), or the shield has no model.
- **The hand**, by the action (`+0x25`): nothing for none (0); the flask's scene (`0x34C5`) for a flask or a potion in hand (3), whichever it is; else, with a weapon (the entity's `+0x24`, the one the sheet wields, not `+0x84`), its own model (`Combatant.WeaponModel`, `0x800668B4`, through `ItemTables.WeaponModels`, `0x8006CDD4`; none for a bite or a claw). A spell changes nothing: the caster keeps its weapon.
- **A bow** (`Combatant.WeaponIsBowKind`, `0x80066908`, the list at `0x800E0C08`) puts the arrow (`0x348F`) in the hand and the bow in the arm, in place of the shield: the bow at locator 1 and the arrow at 0, or the other way round for the eleven whose `+0x84` is 0 (`EntityBody.Hand`, `0x8006C8BC`, a switch on the entity list's place: the bandit bosses and woodsmen, Becan and Keelin).
- **The hand stays empty** for the eight whose models have their weapons (`Combatant.HasNoWeaponAttachment`, `0x80066C5C`, the entity list's places at `0x800D2A0C`: Shamsuk, the Gorgon, the Chaos Lieutenant, the Harpy, the Marquis, the Minotaur, the Minotaur Lord and Niesen, whose staff has a model all the same). It's tested after the arm is filled, so their shield or bow shows.

`EquipVisuals` runs as a combatant is made (`Combat.CreateBody`'s `SetDefaultAction`, the reserves' too), as a flask or potion is taken in hand (`SetSpellAction`) and put back (`RevertAction`), as a turn starts with a flask the party has no more of (`TurnOrder.BeginTurn`), as the pause menu changes a weapon (`Party.StowHeldItem`, then `AfterEquipChange`), after `EnemyAI.SwapWeapon`, and as an arrow, flask or thrown weapon lands (`Combat.EndCast`, `0x80021AE8`): `Combat.StartCastCamera` (`0x80023434`) emptied the hand as it left. A shield can't be changed in battle (`Party.TakeOffShield` refuses in state 14). Nothing breaks: no weapon or shield wears out. Death, flight and the post-battle windows leave what's held on the body until it's freed.

**The Troubadour's notes** go on slot 2 as a performance starts (`Combatant.StartTroubadour`, `0x800662F4`: `AttachItemToPlayer(body, 2, 0x1ABB)`, locator 3) and come off as it stops (`StopPerforming`, `0x80066100`, which `FreeAttachmentFromPlayer`s slot 2, so they're gone the next frame). Borg5 `0x1ABB` is one billboard card of music notes, not a lute (the docs called it one until the user saw it in play): 1.64 square, standing on its foot, unlit, with white vertices, blended, its texture (Borg1 `0x1ABA`, 32 × 32, scroll byte `0x01`) moving a texel toward +S every second draw. Neither function plays a sound, tints the body or starts a particle; the performer's request 5 is the one-shot every cast plays, and no later turn asks for another. Every party member's actor has a locator 3, so any member can show them. The user compared its size, height and scroll with the emulator's.

**Drawing** (`Bodies.Render`, `0x80013DCC`, after the body's own scene): each slot with a Borg5 loads its scene the first time (`BorgAnimLoadScene`, then `Scene.UseOwnMatrix` `0x8009E3B4`, so it's evaluated from its own matrix, and `Scene.EnableFog` `0x8009E590`), and is skipped if the body's actor has no such locator (`Scene.HasLocator`, `0x8009EAE8`). Its matrix is the locator's (`SceneGetLocatorMtx`, `0x8009EB10`, set with `Scene.SetMatrix` at `0x80014260`): the locator model's rotation (`guRotateRPYF` of its Borg2 rotation, [scenes](../formats/scenes.md)), then its position, then its transform as the animation poses it, so the item turns, moves and scales with the hand, the body's scale with it, and isn't turned any more for a shield or a bow. Slot 2 alone (`bnel $s6, 2` at `0x80014290`) is then raised 1.0 (`0x3F800000`) in the world's Y (`Scene.Translate`, `0x8009D970`, which adds to the matrix's translation), whatever the body's scale. A word at `0x800DA490` doubles every attachment's size (`Scene.ScaleMatrix`, `0x8009DC6C`), as its neighbour `0x800DA494` does the heads': nothing writes either by its address, so they're likely the `!bigw` and `!balloon` cheats' ([hardcoded-content](../hardcoded-content.md)), which the port doesn't have. It's lit as the body (`Bodies.SetLights`, whose locator argument is never read: the lights are found from the body's place) and drawn at the body's alpha, so it fades with a body that flees; but its prim colour (`Scene.SetTint` at `0x80014254`) is the scenery's tint times the screen's fade, where the body's own scene keeps white. Then `Scene.Draw` (`0x80097244`), the path every scene takes, so an attachment's billboards face the camera's place (`BorgAnimDrawSceneRaw`) and its scrolling textures move once a draw. A billboard's size is its transform's scale times the scene's scalar (`SceneData.scalar`, which `Scene.SetScale`, `0x8009DBCC`, sets for the body's own scene), and nothing sets an attachment's, so the notes are 1.64 across on any body: the body's scale only moves where the head is. They stand from about 1 to 2.6 above the head's locator. Its look is its Borg5's alone: no glow or texture by the item.

**The port** keeps the slots in the core (`Combatant.Held`, `HeldModel`, the notes `Combatant.NotesScene` and `NotesRaise` in `NotesSlot`) and draws them in the runtime's `BodyView.Hold`: each scene on its locator's attachment node, the notes raised after, with its own copy of its scrolling textures (`ScrollHeld`, at the textures' frame from `Game.ScrollTextures`, as the scenery's: the original's once a drawn frame would be quicker at 30 fps), its billboards turned to the camera with the scene's scalar left at 1 (`FaceHeld`, `Billboards.Face`'s `sceneScale`), and the scenery's tint (`TintHeld`, from `CombatantView.Draw`); the screen's fade is the runtime's overlay. Trek's bodies (a script's `ShowItem`) don't take the scenery's tint or face billboards yet.

Of the entities that carry a weapon, only Zaratas has no locators, so draws nothing; Brenna, Donovan, Godric and Niesen have no locator 2 (none of them can use a shield), and Jundar, Yuli, Edur, Phelan, Pandara, Txomin and Yeraza carry shields their actors have no arm for.

## The special battles

Read from 1.0's code, not run: no checkpoint holds either fight. The combat record carries both as rules ([hardcoded-content](../hardcoded-content.md#bespoke-behaviours), ADR 0008's layer 3): the Goblin Ambush's on its encounter rule, the Shadow's as `ShadowRule`.

**The Goblin Ambush** (encounter flag 978, script `0x0365`; the Shadow isn't in it, whatever the code's names say):

- **As it starts** (`Combat.Init`, `0x80022D1C`): non-lethal, `Combat.ShadowTurnsLeft` (`0x800D94CE`, a byte) 2, and the party's first member healed (`Character.Heal` of its deficit: Endurance, Stamina and the Level's points toward their bases).
- **The hold** (`Combatant.ShadowFightTrick`, `0x80065DCC`), called once by `Combatant.ExecuteAction` before `CheckDeath`, for whatever it resolves (an attack, a flask thrown, a spell's first target; not the Healer, a flask's blast or anything else): when the target's **entity** is Alaron (`0x023F`), the flag is 978 and the damage isn't 0, it queues "%s loses 1 hit point" (`LogHpLoss`, replacing the attack's own line in the one queued buffer), counts the byte down and returns 1, so 1 is taken and shown. When the count reaches 0 (the second hit) the target's Strength goes to 0 (`Stats.AddCurrent(-modified)`, current and modified) and `UpdateActive` finds him unable. The count wraps after, so it never reaches 0 again.
- **The keel-over**: `Combat.ApplyHit` (`0x80021930`) plays the death animation (`Combat.PlayDeathAnimation`, request 9) for a hit on **slot 0** while the count is 0: the second hit's own. At the next turn's change `CountActive` leaves the unable Alaron out, so `TurnOrder.Defeat` loses the battle with the locked line, though he has some 45 hit points; `Advance`'s first-member-dead test never fires. Then states 28 and 13 and the non-lethal ending.

**The Shadow** (entity `0x0226`, place `0xAC`). Its battles are scripts `0x046E` on the Overworld and `0x0497` at Ehud's tower, and the monster parties in H14 and B15 with four Zombies, all closed by flag 566. `Combat.CreateBody` sets `Combat.ShadowSlot` (`0x800D94CC`) for it and `Combat.AlaronSlot` (`0x800D94CD`) for Alaron, and `Combat.FreeBody` clears them; `Combat.Init` clears both but `Exit` doesn't, so they go stale after a battle (hence the mode tests below). The Horn of Kynon (`0x0D03`, `Items.HornOfKynon` `0x800E2A42`) is tested afresh at each use (`Combat.PartyHasHorn`, `0x80023AA4`, through `Party.HasItem`, `0x80079BCC`: the party's inventory or any member's things, the dead's too).

- **Made**: with the Horn, `Combatant.Init` (`0x8005EAE0`) raises its base Dexterity to 30 (`Stats.AddTrained`), for its turns. It can't be attacked (`CanAttack`) or cast by or at (`CanCast`), immobilising effects don't take (`Character.AddEffect`), and it lets the party flee ([In and out](#in-and-out)).
- **Its walk**: with the Horn its goal is combat slot 0's cell, whatever its style chose (`EnemyAI.RunStyle`, `0x80059628`). Every AI path in its battle is cut where it comes within 10 of it (`EnemyAI.ShadowSmoothPath`, `0x8005A734`, from `EnemyAI.PlanPath`): the first leg that crosses the circle ends at `ClipToCircle`'s point, rounded half away from zero, unless the walker's field is 1 (near the Shadow, or the Shadow itself). The AI's walk never works a radius out again.
- **Slowing** ([A turn](#a-turn), step 4): within 10 of it (`Combat.NearShadow`, `0x80023F34`, through `Combat.WithinRadius`, `0x80023D44`: each axis at most 10 and the distance strictly under 10, on the combatants' places) the field is 1, and the current combatant's line is "%s caught in the vortex of the Shadow" (`0x80`), shown and queued. The Shadow's own is 1 with anyone within 10 (`Combat.AnyoneWithin10`, `0x80023E9C`, the dead and gone too). As a player's combatant walks near it, its field and ring follow its body (`Combat.MovePlayerBody`, `0x80084CE0`).
- **The aura** (`Combat.ShadowAura`, `0x80023AD0`, first in `TurnOrder.EndRound`): without the Horn, the round count (`+0x52C8`, which `HoldForMessage` shares) vanishes it at 4 (`sltiu v1, 4`) and otherwise goes up, so the aura works at four round ends and the Shadow goes at the fifth, with no aura then. Then each other combatant in slot order, not gone, dead or of chaos (category 5), under 10 (`0x800CE3CC`) from it, by the places' distance as a float, takes 10 − d, squared without the Horn, truncated. A blow of at least its hit points ends the battle instead (`Combat.ShadowDissipates`), touching no one after. The damage goes through `Character.TakeDamage` (which ends a performance) and shows over the head.
- **Reaching Alaron** (`Combat.CheckShadowMerge`, `0x80023884`, from `Combat.AfterFrame` at every drawn frame's end but in states 17, 29 and 30): once the two bodies' centres are within their scaled radii and 0.5 (`0x800CE3C8`) in 3D (1.8 for 0.6 and 0.7), whoever moved and whatever the state, the battle ends: `Combat.StartShadowCinematic` (`0x80023984`) with the Horn, else `ShadowDissipates`.
- **`Combat.ShadowDissipates`** (`0x800239B4`): with the Horn, the merge (state 17, `Cinematic.Load(1, 4, 1)`); without, state 29, "The Shadow dissipates" (`0xF0`) shown, and every body back to idle.
- **Vanishing** (states 29 and 30): the field is drawn while `+0x52C8` counts on a frame at a time to 60 (56 frames after the fifth round end), then the screen fades out at 1/60 a tick, and state 30 leaves for trek (mode 1) once it's out. `Combat.Exit` does nothing more: no rewards, no flags, the monster party neither remembered nor fled, so trek comes back where the battle began.
- **The merge** (state 17, `Combat.StateShadowMerge`, `0x800226F8`): on its first frame `Combat.MergeShadow` (`0x800675C0`) raises the party's first member from the Shadow's sheet as it stands, and the battle leaves for mode `0xE`. `Combat.Exit` frees it the same frame, and the cinematic (record 1, Shadow Self Merge) plays after. Its end sets its done flag, 569 (`Cinematic.EndCase`), and goes back to trek where the battle began (`Cinematic.EndShadow`). No rewards, no encounter or kill flags.
- **The boost**: Strength +6, Intelligence, Willpower and Endurance +3, Stamina +10 (`Stats.AddTrained`: trained, base, current and modified, the trained byte up to its cap), protection +5 (a byte). Each skill and weapon skill the Shadow has (modified not 0) goes up by the difference of the two base levels (each read to 10 at most, `Skills.BaseLevel`), or 2 if that isn't positive (`Skills.AddSkillBase`, `AddWeaponBase`: the base up to 10, the modified by as much). The shield skill goes up the same way, but only when the Shadow's modified shield skill **is** 0, the test turned round (`Skills.AddShieldBase`). Each of the Shadow's spells goes up the same way to at most 10, or is learnt at the Shadow's level. Then flag 566. On the data the Shadow has Stealth and Wizard 10, no weapon skill, shield 8 (so the shield's branch does nothing) and five spells (`0x031C`–`0x0320`) at 10.
- **Healing barred**, only in combat (`Game.Mode` 2) with the Shadow's slot set: a potion's heal (`Entity.HealPercent`, `0x800715DC`) heals nothing and draws nothing, so the potion is used up and says "%s fails to apply potion". Lay On Hands (`Party.LayOnHands`, `0x80077778`) answers Common line 437, "The Shadow's presence prevents all healing.", before its cost, and Heal With Herbs (`Party.HealWithHerbs`, `0x8007798C`) the same **after** taking the herb and finding the Stamina, so the herb is lost. Either way `ResolveHealer` shows "%s fails to perform healing" over it the same frame (the port keeps line 437), and the turn is spent. The pause menu's Party tab, in mode 3, isn't barred. **Teleportation** fails in `Combatant.ResistRoll` (`0x80064298`) with "%s fails to cast the spell" after its cost is paid.

**Lugash** (place `0xBA`) and **Pochanargat** (`0xAB`) have no code beyond `EnemyAI.HasBossStyle`, `Combat.SetKillFlags` (533 and 3204), Pochanargat's place in `Combat.ForbidFleeForBosses` and his radius of 0 (`Combatant.UpdateRadius`): a scan of every function for their places and IDs finds nothing else. Lugash's first script battle (`0x04D1`) can be fled by its encounter flag 5250, which is derived, so a win never sets it; his second (`0x04D6`) has no flag, and as a cut-scene's battle it can't be fled. He carries a Cheat Death.

**Rain and snow** in combat are trek's: `Combat.DrawFrame` runs `HandleZoneEngineFrame` with the combat camera, and `ProcessWeather` has no combat test ([weather](weather.md)).

## The rest, by entry point

Targeting (`TargetSet`, `0x80068FE0`–`0x8006A0B0`), melee and ranged are [An attack](#an-attack)'s, spells in a turn [Spells, potions and skills in a turn](#spells-potions-and-skills-in-a-turn)'s, the AI [The AI](#the-ai)'s, and the visuals [An attack](#an-attack)'s and [What spells look like](#what-spells-look-like)'s. The rest:

- **Spells, effects, potions and flasks** are [magic](magic.md)'s: casting (`Combatant.CastSpell`, `0x800648CC`, through `CheckSpellAvailable`, `PrepareCast`, `CastChance`, `ResistRoll` and `ApplySpellEffect`), the 15 timed effects and 7 potion records on the entity and their ageing by round and by trek's clock, Cheat Death, the kind lists (`Combat.DispelKinds`, `LimitedKinds`, the charms that count toward the disable limit, `ImmobilisingKinds`), potions drunk, and the flasks' damage and blast. A spell's kind is its place in the spell table, not the combatant's `+0x27`, which holds a potion's.
- **The GUI** (`combatgui.cpp`, `CombatGui.Create` `0x80085B80`) and **the radar** (`CombatRadar.Draw`, `0x8008DF04`): the portraits in their frames down the top left and right with their HP bars, tinted by the target sets, the log box (a `TextBand`, the cinematics' captions' widget) and the radar, centred on the camera's owner and turned with the camera. [ui](ui.md#the-battle-screen) has them. C-left toggles a flag nothing reads.
- **The camera** isn't trek's follow camera: `ProcessCombatCamera` (`0x8008D8BC`, from `Bodies.Process` in mode 2) puts the camera in mode 4 and runs the interiors' `Camera::Mode1` (`0x800A69D8`) with combat's numbers on the body that owns it: near and far 4 and 10 (8 and 16 about the focus in states 11 and 18), the goal 2 above the aim, the aim 1.05 above the body, easing 1/16 a tick at most 1, the eye 1/32 at most 0.5. On its first frame it's put 8 behind the current party member (or the first combatant's body on an enemy's turn), away from the nearest enemy, 1.5 up (`CombatCamera.PlaceBehind`, `0x8008D78C`); a party member's turn puts only its goal there. Through an enemy's turn the eye goes back to its goal and stays, at least 4 from the aim. `CombatCamera.KeepInArena` (`0x8008D29C`) keeps the eye a unit above the floor. State 9's pull-back is [An attack](#an-attack)'s. A spell's cast glides (`CombatCamera.StartGlide`, `0x8008D1F0`; `CombatCamera.CastGlide`, `0x8008D3C8`, checked in 08). No combat code sets the field of view or the clip planes. **Checked** on 02–04. The body it aims at is the camera's owner, which `GiveCameraToPlayer` makes the current combatant's at a turn's start and the cursor's target in states 9 and 10. States 1, 5, 8, 24 and 26 have no branch of their own: the hold on an enemy's turn is by whose turn it is. R orbits it in state 1 as in trek.
- **Random numbers** are the one stream (`Rng.Range` `0x80093214`, its state at `0x800D8088`): the turn order, d100s, damage dice, 2d6 for morale and casting, and loot. The checkpoints hold the stream's state, so a battle's draws can be replayed from one (2.9).

## What it shares with trek

- **The zone engine**, in mode 1, framed each combat frame (`Combat.DrawFrame`) and freed after: the chunks, collision, scenes, lights, sky, rain and the terrain (`World.SetTerrain` every frame), with trek built again after; the port's arena is a stage of trek's `ZoneEngine`, as a cut-scene's is.
- **Bodies**: `AllocPlayer` and `FreePlayer`, `Body.SetDown`, `Body.Face`, the player handler with a goal for the AI's walks, shadows to 128, and the actors' requests (7 hit, 9 death).
- **The UI**: `TextBand`, the pause menu in modes 3, 5 and 6 (the flee option only in state 14), `MenuTween`.
- **Particles and lights**: actors' emitters, the party lit by the map's lights (`+0x70A`, [rendering](rendering.md)).
- **Scripts and flags**: the game over scripts, the encounter, boss and Sholeh's flags, the beaten monster party remembered, the Shadow's cinematic, the battle music with the map set.

**The combat strings** (String/Combat, 64 lines, [text](../formats/text.md)) are taken by byte offset: `0x00` "begins action", `0x04` the party flees, `0x08` victorious, `0x10`–`0x1C` healing, `0x20`–`0x38` avoid, attack, hit, critical, miss, `0x3C`–`0x4C` potions, `0x50` killed, `0x58`–`0x70` spells, `0x74` the Shadow, `0x78` flees, `0x7C` joins, `0x80` the vortex, `0x84` rests, `0x88` changes weapons, `0x8C`–`0xBC` a combatant's details (nothing in combat's files shows them), `0xC0`–`0xD0` performing, `0xD4` the party incapacitated, `0xD8` `flee%d`, `0xDC` `%s%u%c`, `0xE8` banished, `0xEC` "Enemy reinforcements flee", `0xF0` the Shadow dissipates, `0xF4` and `0xF8` `good` and `bad`, `0xFC` "cheats death".

### What a battle tells its host

Combat's presentation goes out as cue records through a host, and its ending comes back from its step (ADR 0019, `CombatCues.cs`).

- **The host** is `ICombatHost`, with one method, `Cue(CombatCue)`. The session takes it at `GameSession.Start` (`combatHost`, the runtime's `Game`) and gives it to `Battle.Begin`, so the first bodies are cued as they're made; a test sets `Battle.Host` on a battle it built.
- **The cues**, in the order the battle makes them. The views build and free their parts by them and read where things are from the battle's state each frame; nothing diffs the battle's lists.

  | Cue | When | The runtime |
  | --- | --- | --- |
  | `CombatantJoined` | a body is made (`Add`): at the setup and as a reserve joins | makes its `CombatantView` |
  | `CombatantAnimated` | a one-off request through `Battle.Animate`: the swing 12–18, the throw 15, a cast or a drink 5; as the blow lands the hit 7, the dodge 8, the fall 9, an ally's help 10 | nothing: the core steps the actors |
  | `CombatantDied` | `Death`, as the killing blow is dealt, before it lands | nothing |
  | `CombatantGone` | a dead or fled body's fade is over (`Fled` says which) | frees the view |
  | `NumberShown`, `NumberGone` | a number shown; its two seconds over, the pool's oldest pushed out, or its body gone | `CombatNumbersView.Show`, `Remove` |
  | `MissileLaunched`, `MissileLanded` | `StartFlight`; `StepFlight` as the blow lands | `MissileView.Launch`, `Land` |
  | `SpellVisualStarted`, `SpellVisualEnded` | `SpellFx.Start` or `StartPotion`, once the cast knows both its bodies, so an actor's emitters attach to the right ones; `FreeIfFinished` | `SpellFxView.Started`, `Ended` |
  | `LogLine` | every change of what the log box says (below) | nothing: the box draws `CombatLog.Text` |
  | `BattlePaused` | the tick the pause menu's two frames have passed | nothing: the session acts on the step |
  | `BattleEnded` | `EndAs`: the win, the loss, the spared loss, fleeing by the pause or by Escape, the Shadow vanishing or merging | nothing |

  The battle's own `Free` at its end cues nothing: `BattleEnded` came first.
- **The step**: `Battle.Tick` returns `BattleStep.Ran`, `Paused(PartyTab, CanFlee)` while the pause menu is due (the Party tab and Flee from a turn's pause, states 1, 9, 10, 11, 18 and 25; the System tab alone from state 27's), or `Ended(Outcome)` once it has left (`Battle.Over`: states 16, 20 and 21). The session sends `Transition.PauseBattle` on the first and keeps the outcome of the second for `EndBattle`.
- **The log's one writer**: `CombatLog` notes in `History` (`Battle.Log`) and cues as `LogLine` every change of what the box says (`Text`): a line shown at once, a queued line or Banish's third flushed, the reinforcements' hold and the line it gives back, and the line it's locked on. A line put up over itself isn't one, as the box doesn't change. So the log holds what the player saw when they saw it: a blow's queued "loses %d hit points" as the blow lands, a spell's "cast on" at state 2's end.
- **The session**: trek cues a battle (`TrekLoop.CueBattle`, `QueueState(2)`'s fade at 1/30 a tick) rather than handing it to the host, and cuts the music as it goes (`TrekLoop.BeginBattle`). `GameSession.BeginBattle` stages the arena on trek's zone engine as a cut-scene's stage (`ZoneEngine.Stage`), its music held until the fade ends, begins the battle (mode `GameMode.Combat`, under the menu) and sends `Transition.StartedBattle`. `GameSession.EndBattle` cuts the music whatever the outcome ([audio](audio.md#music)), sends `Transition.EndBattle`, calls `Battle.Leave`, moves trek's kept place for an encounter's end (`TrekLoop.Keep`), then by the outcome: won, it holds the world as `PostBattle` and sends `Transition.PostBattle`, and trek comes back where the battle began once the windows close (`MenuClosed`, [ui](ui.md#after-a-battle)); lost, the game over (`PlayGameOver`: the combat record's `GameOver` script from its dialogue object in the Dreamscape's map, as a cut-scene, whose end is `Transition.GameOver` by the base plugin's trigger on its `script.ended`, [events](events.md)); merged, the Shadow's cinematic (`PlayCinematic(cinematic, fromTheatre: false)`), whose end resumes trek where the battle began; otherwise `TrekLoop.Resume(fled)`, at the farthest breadcrumb having fled, with its heading and the camera at its eye ([In and out](#in-and-out)), and `Transition.ResumeTrek`.

### Traps

- **A tick's order** (`Battle.Tick`, as `Combat.Frame`): the reinforcements' hold; the controls; each body in turn (`AtStrike` reads the frame before the actor steps, then the step, the push and `AfterBodies`); the camera; the state's step; the Shadow's reach (`CheckShadowMerge`); the marks; the tints; the spells' visuals; the numbers; the fade. The marks set and clear tints before the tints step, so a cast's glow on a body the marks let go is cleared on the frame it starts, as checkpoint 08's tints (all 0) show.
- **A one-shot request is held a frame.** `Combat.AfterFrame` lets requests go once a frame, so a request combat makes is asked for through every tick of its frame (`Combatant.OneShot`, `Cadence.FrameTicks`), and an actor takes only a request its state has a branch for (`ActorStateMachine.Taken`), so the frame's second tick doesn't advance it. Without both the swing's, hit's, dodge's and death's keys don't sound ([audio](audio.md#bodies-sounds)).
- **The blow lands at the strike**, not the swing's end: `AtStrike` before each body steps, `AfterBodies` letting `Body.Playing` (`+0x18`) go there, the share `EntityBody.Strike` or `EntityBody.DefaultStrike` for requests 14 and 15. The missile leaves at the same check.
- **The original's one focus is three aims**, each moved only by its own: `Battle.ThrownAim` (state 18's free cursor), `AreaAim` (state 11's centre, which set B is built about for the player's placed spell) and `AiAreaCentre` (the AI's `AreaCentre` and `AimAreaSpell`, which an AI's placed spell is cast about). `FocusOn(c)` puts all three on a combatant wherever the original puts its focus there, so each reads what the original's would; the camera looks at its state's.
- **The AI's tries are built in their own target sets** (`Battle._triesA`, `_triesB`), not the battle's, which hold the turn and the player's aim. An attack try moves the combatant's place to the cell and back (`TryAttack`, the action passed rather than set), as the original's does, and must: the reach's reads of the bodies (`IsWithinReach`, `FreeOfOpponents`) and an opponent's field worked out again (`UpdateRadius`, `NearShadow`) read the place and put it back where the body stands, which is why melee counts only the body's place. A spell try reads nothing of the bodies, so it asks `CanCast(c, source, t, from, centre)` and `SpellTargetCount(c, source)` of the slot's spell (`Combatant.SpellOf`) without selecting it or moving anyone. Each leaves the battle's sets as the original's tries would: the attack tries empty set A, the spell scores start from set B's cursor and empty it, and Fireball's aim leaves set B its last try's cursor, which `PrepareTargetSets`' rebuilding keeps (`TargetSet.TakeCursor`).
- **A body keeps its cell while it hasn't moved** (`Combatant.SyncFromBody`): the port's bodies are in the world's coordinates and the original's in the arena chunk's, and taking the chunk's origin off loses a little, enough to move a cell after the AI's tries. `IsWithinReach` is false for a body gone from the field.
- **The fading.** `FreeBody` sets `Combatant.Fading` to `Battle.FadeTicks` (120) for the dead and the fled alike and keeps the combatant in the battle's fading list, which a reserve taking its slot doesn't empty. `Battle.Crowd` counts each down a tick, cues `CombatantGone` at 0, and keeps the fading among the bodies that push and are pushed, stepped with no animation, in slot order with a fading body before the reserve in its slot. `Combatant.Alpha` is the body's `+0x70C`: 255, then `(u8)(left / 60 × 255)` under `Battle.FadeShownTicks`. The next turn begins as the fade starts.
- **A weaponless action**: the original's `CanReachWithWeapon` takes a melee or ranged action without a weapon away (`+0x25` to 0) as it tests it; the port's leaves it, since it reaches no one either way and everything after treats an action without a weapon as none.
- **Seven of the visuals' actors are particles alone**: the refused and resisted casts' (`0x1CAA`, `0x37F1`), Dragon Flames' target's (`0x1C55`), Banishing's and Escape's target's (`0x1C9F`), vs. Star's and Wraith Touch's casters' (`0x1E9D`, `0x1EF7`) and the Fire Flask's (`0x1A56`). Their scenes have no models and every animation of theirs holds still, so their glTFs have no animations (the still ones are in the extras, [animation](../formats/animation.md)) and Godot gives them no animation player. `ActorAnimator` runs such an actor without one, its states timed by the still animations and its emitters started by its requests; until it did, `SpellFxView` drew nothing for them and the core ended them at once, so a failed, refused or resisted cast showed nothing. Their glTFs have no geometry and so no binary chunk, which Godot's reader warns about; `Models` made such a scene a bare node, without the locators its emitters start at, so each emitter ended as it started and they still showed nothing (the Fire Flask's flames on its target, which the user saw in 1.0) until `GlbFile.LoadNodes` built their nodes from the glTF.
- **Content by its effects, not its kinds**: Darkness and Light are known by their `partOfDay` effect, the holds by `immobilise` (`Combatant.PoseHeld`), Fireball by its spell record's `area`, the Shadow by its `ShadowRule`. The original tests the Shadow's place (`0xAC`) in `ForbidFleeForBosses`, `CanAttack` and `CanCast` with no list; the record keeps two rules, `Flee` and `Untargetable`, so a mod's boss the party may flee from can still be hit.

### Where the port differs

The user's choices:

- **An attack's line of sight runs head to head**, where 1.0's lifts the attacker's point by both heads and aims at the target's middle (`Combatant.CanAttack`'s pasted block, [An attack](#an-attack)). In the README's fixes. Two of the casters' 118 replayed cases turn on it.
- **A flask's target shows and says all it lost**: the blast takes its share and the blow takes it again, as 1.0's do, but the queued line and the blow's number give both (`Battle.FlaskExplosion` returns what the blast took, which `Land` adds to the number), so a rat of 31 hit for 10 is left with 11 and shows 20. Sleep Gas's blast drains Stamina, which hit points count, so its target shows 30. The user saw 1.0 and 1.1 show half of what was lost, and chose to keep the damage and fix the display.
- **The aiming cursors' frame is 4 ticks** (`Cadence.AimFrameTicks`), 0.2 a tick, for state 18's free cursor and state 11's area: the Combat checkpoints' frames were 2 to 4 ticks (`Frame.Delta`, `0x800D8094`), 4 in both aiming states sampled, and at the port's usual 2 the user found the flask's circle twice as fast as the console's and hard to steer.
- **The last flask of a stack flies and bursts** as the others do: the port leaves a thrown flask in hand until the turn's end puts the action back, where 1.0's `ConsumeFlask` empties the hand as it's thrown. In the README's fixes.
- **Escape doesn't softlock**: state 2 goes on to the result when its target has left the field, a caster that has left still casts at the rest of its targets, and with every member able to fight gone the party has fled (state 20) at the next turn's change. Not in the README, as only cheating reaches the spell.
- **The Healer refused in the Shadow's battle says why**: Common line 437 stays shown and queued (`HealingBarredLine`), where 1.0's `ResolveHealer` overwrites it the same frame with "%s fails to perform healing". In the README's fixes.
- **The Goblin Ambush's end sets the leader's Strength to its base** rather than adding the base to it, which doubled it when the battle ended before the second hit.
- **A script's battle has no bonus loot**, where the original pays out the last monster party's again (`0x800D9470` is never cleared).
- **The game over's end goes back to the title**, its cards first, as the original's does, but the runtime starts its Godot scene again with a new game for it ([ui](ui.md#coming-back-to-it)).
- **The lasting scenes' turns** are the original's by default, one at a time across the battle, which may be its designers' way of keeping effects from crowding the screen. The options' Spell auras (`Settings.SpellAuras`, `SpellFx.Turns`, `AuraTurns`, which the session sets from each tick's `SessionSettings` and as the battle begins) can show each character's at once instead, each over its own head with its own hump and loading. The 5 seconds after a cast hold both. An enhancement as [ADR 0018](../adr/0018-the-port-fixes-bugs-and-sets-enhancements.md) has them.
- **The Pace setting quickens a turn's walk.** Brisk's 1.3 (`Battle.Pace`, which the session sets from each tick's `SessionSettings` and as the battle begins) plays the body the player steers in state 1 faster, steps and all, as trek's player's ([movement](movement.md)), the user's choice. It doesn't reach the field's radius, so a turn covers the same ground sooner, nor the AI's bodies, nor the attack, cast or turn's end after it, whose timings the strikes and the results wait on.
- **Kept as the original's**: a flask's blast keeps its distance in a byte, so far combatants can be hit ([magic](magic.md#potions-and-flasks)); Heal With Herbs in the Shadow's battle loses its herb before the bar refuses it, as a potion drunk there is used up for nothing; Acid thrown and missed corrodes about the last flask's cell (read, not run).

Not ported:

- `Talk`'s collision byte: a monster party used is collision 0, so its enemies face 5–7 even used from behind (1 would face them 1–3).
- Combat's frame counter's limit on pausing (`+0x5448 < 4`).
- Half-alpha shadows: `EntityBody.ShadowAlpha` (`0x8006C798`) gives entity list places `0xAF`–`0xB5` and `0xC0` a shadow of alpha `0x7F`; the port draws every shadow whole.
- The idle bodies combat leaves still: `Bodies.Process` doesn't step the animation of an idle body (its request, `+0x1A` and `+0x1C` all 0) 13.0 (`0x800CDB50`) or more from the camera's aim, unless its actor is in `Body.AlwaysAnimated` (`0x800CDA50`, nine actors, read onto the actor records as `AlwaysAnimated`, [hardcoded-content](../hardcoded-content.md)); the port steps every body's but the held and the fallen.
- An arrow, flask or thrown weapon leaves from the hand's locator as the runtime last drew it (`Combatant.LocatorAt`, which the runtime sets from `CombatantView.Locator`), but from the attacker's middle (its feet plus half its height) for an actor without that locator, where `Combat.StartCastCamera` flies nothing, and in a battle with no runtime.
- What a body holds is lit by the lights at the body's centre, not at its locator.
- The glide aims by the attacker's entity height less 0.2 and its radius; the original's `EyeHeight` (`0x8006C748`) isn't read.

By the tick:

- The camera acts every tick rather than once a frame; only its goal and holds are once-a-frame things, so it's the same at 30 fps.
- The action's timers are counted and tested every tick, not once a frame, so where an attack's strike frame is odd its blow lands a tick sooner than at 30 fps (a goblin's Sabre at 81 rather than 82), and state 6's snap takes two ticks rather than two frames.
- The AI's walk counts a tick's move toward the stuck timer, times a 30 fps frame's ticks, where the original counts a frame's; its body's 30 ticks of no progress are counted once a 30 fps frame by 0.01 a frame, two ticks at a time, as all steering toward a goal is ([wanderers](wanderers.md)). The stuck test leaves out the original's actor-speed term (an actor standing moves under 0.03 anyway).
- The Shadow's reach is tested every tick rather than at each drawn frame's end, and state 29 counts its frames by the cadence.
- The spells' visuals step every tick; their timers are the same at 30 fps, and a lasting scene loads 10 ticks after the last rather than 5 frames.
- Held, the stick and D-pad repeat an aim's cursor and a held menu's rows as the runtime's menus do; the original steps an aim once a press and repeats a menu after 30 polls and then every 5.

Others:

- A bystander in the first four leaves the original a null slot that it counts as an enemy on the field; the port leaves it out and says so (`Battle.Problems`). No monster party that fights has one.
- The ring starts each layout due +Z rather than a hair further round than the last (the original's statics drift by float error).
- The original runs `Execute` after `FleeAdvance` even for a fleeing enemy that has just left, its body gone; the port stops there.
- A walk the AI gives up is forgotten at the turn's end; the original's body would run on into the next turn.
- The loot is rolled on the loot stream, not the battle's (ADR 0006), so a battle's draws after it don't shift.
- A win leaves through state 16 (`Battle.Over`), which the original never reaches for one, and the session opens the windows; the post-battle window opens on `PauseMenu.Member`, the member last shown or whose turn the last pause was on ([ui](ui.md#opening-and-closing)).
- Detect Moon Phase and Detect Sun Phase do nothing in a battle; the original writes through a null pointer. Play never reaches it: the user knows no way to learn either, and takes them for cut content.
- A placed area confirmed with no one in it goes back to the turn, as state 10 does with none selected; the original's branch for it wasn't read.
- A cast beyond the visuals' pools shows nothing, where the original's reads past its free list; no battle comes near 64 lasting effects.
- Body armor or a shield equipped from the combat pause's Party tab is refused with "You cannot equip that item!": the original's equip table has no row for them, so it looks to refuse them so.

## Not settled

- **The Shadow's battle** is read, not run: no checkpoint holds it, so the aura, the vanish's frames and the merge's boost are matched to the code alone ([user-checks](../user-checks.md#combat)). The Goblin Ambush's hold, also read alone, the user has seen play as the port has it.
- **The merge's shield test**, turned round in the original (the skill goes up only when the Shadow has none): whether to keep it or turn it the right way isn't chosen. The data never reaches it, as the Shadow has shield 8.
- **The frame's `delta` in combat**, taken as 2 ticks; checkpoint 10 suggests 3. It sets how long a one-shot request is held and rounds an attack's strike to a frame ([reference rig](../reference-rig.md)).
- A fleeing enemy whose leg can't start goes on to `Execute` after `FleeAdvance` (`0x8005B3D0`–`0x8005B418`), so a cornered one may still attack; no case was run.
- The actor field `+0x34` in state 5's stuck test (about 0.037 for a running rat), taken as its speed.
- Exactly which cone `Talk`'s collision byte tests (`0x80010AE8`–`0x80010B74`).
- Body flags `0x200` (set on enemies' bodies by `Combat.CreateBody`), `0x400` (skipped by the bodies' push) and `0x800` (`Bodies.Process` calls `0x80015FEC`), which `TurnOrder.ClearActions` clears.
- Exactly where in 05 to 06 the attack's draws fall, which a watchpoint on `0x800D8088` from 05 would show.
- What only the emulator shows, in the [user checks](../user-checks.md#combat): Darkness's and Light's sky and a hold's still pose. Endurance's casts are captured (`roms/combat-castingendurance*.png`, on Brenna and then Rheda) and the user found the shell, the sky's dimming, the glow and the lasting turns match.
