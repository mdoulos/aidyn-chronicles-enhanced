# The runtime (M1–M4)

`src/AidynRenewed.Game` is the Godot game. It references `AidynRenewed.Plugins`, `AidynRenewed.Core` and `AidynRenewed.Views`, and not `AidynRenewed.Rom`, so the build enforces ADR 0001. It draws with what it shares with the editor in `AidynRenewed.Views` (ADR 0022); the rest of its views, and `Game`, which `Main.tscn` attaches by path, are its own. Import first ([importer](importer.md)), build with `dotnet build`, then run it with `tools/godot.ps1 --path src/AidynRenewed.Game`. It reads the plugins from the data folder, so set `AIDYN_RENEWED_DATA` for both if the import went elsewhere. It refuses a base plugin that's missing or was imported by another importer (`BasePlugin.Diagnose`), with the words the CLI and the editor use.

The runtime keeps its loops thin (ADR 0012): the core's `GameSession` plays the game, and the runtime draws what each tick leaves and carries out what it asks. Each system's doc says how its part is drawn; this one says how they fit together, and holds the controls and the command line.

## The data folder

The plugins, the saves and `settings.json` live in the data folder (`DataPaths.Root`, in `AidynRenewed.Plugins`), which the game, the editor and the CLI resolve alike:

1. `AIDYN_RENEWED_DATA` if it's set, which the tests, the tools and development use.
2. Else a portable install's `data` folder beside the executables, when the app's folder holds `portable.txt` (the Windows portable zip ships it) or already holds an import there (`data/plugins/aidyn.base`).
3. Else `Aidyn Renewed` in the local application data folder: `%LOCALAPPDATA%\AidynRenewed` on Windows, `~/.local/share/AidynRenewed` on Linux, `~/Library/Application Support/AidynRenewed` on macOS. The MSI install and the Linux tarball use it.

`AidynRenewed.Plugins` doesn't know Godot, so the app folder is handed in: both Godot apps call `AppLauncher.UseAppFolder` (in `AidynRenewed.Views`) from their main node's static constructor, before any field reads a path, and it calls `DataPaths.UseAppFolder` with the executable's folder only when exported (`OS.HasFeature("template")`) and not on macOS, whose app bundles have no portable mode. The CLI never calls it, nor do the apps run in development, so those go by steps 1 and 3. `DataPaths.Resolve` is the rule over its inputs, which `DataPathsTests` checks.

## With no import

At startup, before anything loads, `Game` asks `BasePlugin.Diagnose` whether the base plugin is there and current. If it isn't, the game starts the editor with `--from-game 1` and quits, and the editor's import page imports and then offers **Play** ([editor](editor.md#the-import-page)). `AppLauncher.LaunchEditor` finds the editor beside the game: exported on Windows and Linux, `aidyn-renewed-editor(.exe)` in the same folder; on macOS, `Aidyn Renewed Editor.app` beside `Aidyn Renewed.app`, through `open -n … --args`; in development, the same Godot binary with `--path` the repository's `src/AidynRenewed.Editor`, found from `res://`. If it can't find or start it, or the run takes a screenshot, the game shows `Diagnose`'s words in its window as before, with a line saying to open the editor.

## How a tick runs

`GameSession.Start` builds the game where a `GameStart` says (a save's place, or a new game's arrival with the command line's overrides, `Game.StartingPlace`), and the runtime builds its player and camera views from `TrekLoop.Player` and `Camera`; the tests start their sessions the same way. Then `Game._PhysicsProcess` calls `GameSession.Tick` once per 60 Hz tick, which in order:

1. hands on the settings if they changed (`GameSession.Apply`), before anything steps ([ADR 0023](../adr/0023-the-core-is-handed-its-settings-each-tick.md));
2. counts the tick, in every mode: the time played and the game's ticker (`GameState.CountTick`, [saves](saves.md), [cameras](cameras.md#camera-objects-processvoxelcamera));
3. repeats the held directions (`StepStick`, [ui](ui.md#opening-and-closing));
4. steps the pause menu by the scroll actor's clock (`ScrollClock`); if it has closed, the session carries out its exit, gates the map again, and the tick returns `SessionStep.MenuClosed` without stepping a mode ([ui](ui.md#opening-and-closing));
5. steps the mode that runs (`GameSession.Mode`, by precedence the title, a cinematic, the credits, the pause menu, a backdrop's page, a map object's popup, a conversation, a cut-scene, a battle, else trek): trek's `TrekLoop` ([map objects](map-objects.md), [wanderers](wanderers.md)), a cut-scene's `CutScene.Tick` ([scripts](scripts.md#cut-scenes)), a battle's `Battle.Tick` ([combat](combat.md#the-port)), a cinematic or the credits ([cinematics](cinematics.md), [ui](ui.md#the-credits)), or the title's cards and fly-throughs ([ui](ui.md#the-title-screen));
6. fades a backdrop's page (`Trek.StepBackdrop`, [ui](ui.md#books-and-the-help-menu)) and twinkles the stars (`Sky.StepTwinkle`, [rendering](rendering.md#the-skys-objects)).

The tick returns a `SessionStep`, and the runtime draws the mode it names, holding the world's views still by `GameSession.Mode` rather than working it out. When the step says trek has faded out or a cut-scene or battle is over, the runtime calls `BeginCutScene`, `EndCutScene`, `BeginBattle` or `EndBattle`, and draws around them. Everything else the core asks comes through its hosts, which `Game` is:

- `ITransitionHost.Transition`: every ending of a mode, the menu or a script, in order, decided in the core (`Transition`; a script's in `Transition.AfterScript`, [scripts](scripts.md)).
- `ITrekHost`: conversations shown in the box, the loot window, chunks gated again (`Regated`).
- `ICombatHost`: a battle's one-offs as cues ([combat](combat.md#what-a-battle-tells-its-host)).
- `IPauseMenuHost`: the menu's cues. `PauseMenuView` only binds the tabs' views to each opening's models and lays them out ([ui](ui.md#the-pause-menu)).

A press is the session's too: the runtime turns Godot's event into a `MenuAction` (`MenuStick`), and `GameSession.Press` sends it to the mode that runs and says what it came to (`PressOutcome`, [ui](ui.md#opening-and-closing)). `Game._Process` draws between ticks, and Godot's physics interpolation smooths bodies.

## What it draws

- **The world** a mode plays in is a `ZoneEngine` (the original's `InitZoneEngine` and `HandleZoneEngineFrame`): the chunks with their collision, sounds and lights, the music, the weather and the sky. Trek has one, a cut-scene's stage is another made from it (`ZoneEngine.Stage`, [scripts](scripts.md#the-world-it-plays-in)), and a battle's arena is a stage on the Battle arenas. `ChunkStreamerView` draws its chunks' scenes, scene objects and actors ([rendering](rendering.md)); `SkyView` pushes its sky to the shaders, with `SkyBackdropView` and `LensFlareView` ([rendering](rendering.md#the-skys-colours)); each frame's lights start with `ZoneEngine.BeginLightFrame` ([rendering](rendering.md#point-lights)).
- **Bodies.** The player is `Game`'s (`Player`); every other body is a `BodyView`: `WandererView`, `CutSceneActorView` (with the item in its hand) and `CombatantView` ([combat](combat.md#the-port)). A `BodyView` holds the actor at its scale, faded and lit, with its shadow (`ShadowDecal`, [movement](movement.md#shadows)); the core's `ActorMotion` times it and `ActorAnimator` poses it ([actors](../formats/actors.md)).
- **Screens.** `HudView` and the battle screen's views, `PauseMenuView`, `TrekPopupView`, `BackdropLayer`, `CinematicLayer` and `CreditsLayer` draw what the core's models hold ([ui](ui.md), [cinematics](cinematics.md)).
- **Audio.** `AudioOutput` plays the core's `GameAudio` on its own thread through a Godot generator stream ([audio](audio.md)).
- **Settings** ([ADR 0013](../adr/0013-settings-in-the-options-menu.md), [ui](ui.md#options)) are kept in `settings.json`, with the command line's lying over them (`LaunchSettings`). `Game.ApplySettings` makes the session's `SessionSettings` again as they change, and carries out what's only drawn (the window, v-sync and the frame rate limit, anti-aliasing, the 3D resolution, Draw Distance and Object Distance, model detail, the UI's lines and filter).
- **Saving.** F8 saves to `quick.json` in the saves folder, with where the player stands (`GameSession.NotePlace`). Loading from the System tab or the title reloads the Godot scene from the save, keeping the plugins loaded ([saves](saves.md), [ui](ui.md#saving-and-loading)).
- **The title** ([ui](ui.md#the-title-screen)) is a mode over a new game's session (`GameSession.ShowTitle`), which `Game.Start` shows on a plain launch: `TitleLayer` draws its cards, logo and menu, and `Game.Title.cs` its fly-throughs' scenery and camera. New Game ends it into the same session's game. The game over and the ending's credits start the Godot scene again on the title (`Game.GameOver`), as the original restarts at it, and so does Quit Game's Return to Title, at the logo (`Game.ToTitle`); its Quit to Desktop, and the title's Quit Game, end the program (`Game.Quit`, [ui](ui.md#the-system-tab)).

## Traps

- **Cadence** ([ADR 0017](../adr/0017-the-core-steps-every-tick.md)): where the original acts once a frame, the port matches an idealized 30 fps, a `delta` of 2 (`Cadence`), the user's choice; the console runs at 15–25 fps. Code that acts once a frame counts its ticks with `FrameGate`.
- **Nothing in the core reads `Settings`** but the options menu, which changes them. The rules play by the `SessionSettings` each tick hands in; headless tests hand `SessionSettings.Original`.
- **Trek's chunks stream only while its world is built** (`GameSession.StreamsTrek`). `Game._Process` moves the 3×3 with the player or the free camera, under the pause menu too, but not under a stage, an arena or the post-battle windows, where loading trek's chunks would play their sounds. Then it brings Draw Distance's ring of scenery round the 3×3 (`SceneryRing`, [rendering](rendering.md#draw-distance)), in trek alone.
- **A loaded chunk is known by its `ChunkKey`**: map set, row and column. Collision, drawn surfaces, map objects (`LoadedMap.Key`), trigger triangles, an arena's grid and a stage's rain all name it, so two map sets' I08 are never taken for each other.
- **Gating.** A scene object is placed only if its flag gate holds as its chunk loads (`LoadedMap.Activate`), not every frame. The original decides again whenever it reloads the map (`loadGameBorgScenes`): after the pause menu, a shop, training, a battle, a cut-scene or a teleport, but not after a conversation in trek. The port gates again as the pause menu closes (`TrekLoop.Regate`, rebuilding each chunk whose objects came or went through `ITrekHost.Regated`), and after a cut-scene, a backdrop or the help menu reloads the chunks and their wanderers where the player stands (`TrekLoop.Resume`, [wanderers](wanderers.md#joining)).

## Loading chunks

[ADR 0025](../adr/0025-chunks-load-off-the-main-thread.md). Crossing into another chunk loads the chunks that come into the 3×3; the original stalls as it does, and the port spreads the work.

- **On the main thread, as the chunk loads** (`ChunkStreamer.Update`, from `Game._Process` on a crossing and from trek's tick on a teleport or a reload): its collision, its map objects activated by the flags (`LoadedMap.Activate`), its drawn surfaces, its sounds, lights and wanderers, and each wanderer's view with the motion the core steps its body by (`BodyView`), which rolls on the game's animation stream. So is the scenery of a chunk within three quarters of a chunk of where the 3×3 was loaded about (`ChunkStreamerView.NearBuild`), the chunk the player is in among them, and a wanderer's body within 40 of it (`NearBody`), and every view of a cut-scene's stage and a battle's arena.
- **On the builder's thread** (`ChunkBuilder`, one job at a time): the scenery of the other chunks the 3×3 loads, 100 away on a crossing, and of every chunk of Draw Distance's ring, built outside the tree from the objects as they stood when the chunk loaded, and the rest of the wanderers' bodies. Then, while nothing waits to be built, it reads ahead what the next crossing could load: for the chunks two from the centre, their drawn surfaces' triangles (`ChunkStreamer.Prepare`), their scenes and objects (`Models.Warm`) and their monster parties' actors, and under the ring, the scenes of those three from it. A new centre drops what was still to read.
- **Back on the main thread, a frame or a few later**: `ChunkStreamerView.Flush` adds one built chunk a frame to the tree, leaving out an object put out since its build began, and each wanderer's body as it's built (`BodyView.TakeBuilt`), whose emitters start then. A chunk going from the 3×3 into the ring or back keeps its old scenery drawn until its new scenery is added (`Settle`), so nothing goes missing as it changes hands.

Traps:

- **The main thread must never wait on the builder.** Godot's renderer serves another thread's calls on the main thread between frames, so the builder can be waiting on the main thread. `Models` parses its own copy of an asset the builder is parsing rather than wait, `N64Material` compiles a shader outside its cache's lock, and `ChunkBuilder.Dispose` serves the renderer while it waits for the job under way. A lock the main thread can take, held across a call into the renderer, deadlocks the game.
- **Calls into the renderer from the main thread wait while the builder makes resources.** Setting the follow camera's far plane every frame cost about 6 ms on the frames the builder was busy; it's set only as it changes. Something the main thread calls every frame should be cheap on the renderer's side.

## Stand-ins

- Alaron's head follows his neck, where the game keeps it upright and turns it toward nearby objects.
- **The spawn point.** A rock stands in a hole in the terrain in front of it, with collision walls and no top. The original drops the player from a height of 10; the runtime puts him on the highest ground below the spawn instead.

## Controls

Every control can be rebound on the options' Controls page, on the keyboard with the mouse and on a controller apart; [ui](ui.md#controls) lists them by situation with their defaults, which are what's below ([ADR 0026](../adr/0026-controls-are-bound-by-situation.md)).

- **How input is read.** The bindings (`Settings.Controls`) become Godot's input actions as the game starts and whenever they change (`InputBindings.Apply`, from `Game.AddInputs`): one action per button, named for its control (`menu_accept`, `battle_spells`), and four per direction, its sources' directions: `move_*` for Move's own sources, `steer_*` for those Move and Camera share, `look_*` for Camera's own, and `menu_*` and `target_*` for the menus' (a conversation's too) and a battle's. `MenuStick` translates an event by the controls of the situation the game is in (`Situations.Of(GameMode)`), and `Game.ReadInput` (in `Game.Input.cs`) reads the stick, the camera and Sneak for trek and a battle's turn. Nothing reads a key directly.
- **Moving.** WASD, the arrows or the left stick. The stick walks under 80% tilt and runs above; on a keyboard, Ctrl walks. Shift or a click of the left stick runs in full, the user's addition ([movement](movement.md#the-full-run)). C or the left trigger sneaks (Z on the N64). The keys were Shift for walking and Ctrl for sneaking before the full run; a player who rebound them keeps theirs.
- **The camera.** The original orbits it with R and the stick, and Alaron can't move while it does. Here that's Camera Hold (the right shoulder) with the left stick; the right stick, Q and E, and the mouse with the right button held turn it while he walks (a port addition). With the mouse on the Camera row the mouse always turns it, captured in trek and a battle and let go in the menus, a conversation and the free camera (`Game.CaptureMouse`). See [cameras](cameras.md#the-follow-camera-cameramode0).
- **A** is Space or the bottom face button: it uses the map object the player reaches, and closes or chooses in a popup. **B** is Backspace or the right face button: it closes a popup, or with none raises or lowers the party's portraits. **Start** is Enter, Escape or Start.
- **In a battle:** the party member whose turn it is walks in its field as in trek, and Z or the left trigger with the stick still skips the turn (Z or L). A (Space) with the stick still aims an attack at what's in reach; then left and right (the stick, the D-pad, A and D or the arrows) step the target, a bow's or thrown weapon's by Q and E (C-left and C-right) with the stick moving a free cursor, A attacks it, and B (Backspace) or Z puts it away.
- **In the pause menu:** Z and X or the triggers change the tab (Z or L, and R); Q and E or the shoulders change the member (C-left and C-right, C-left showing the next); the movement keys, arrows, left stick or D-pad change the list and move the cursor; Tab or the top face button shows the details while held (C-down); R or the left face button is C-up in a shop. In the name entry the keyboard types. Hovering a row or the wheel moves the cursor.
- **The debug keys aren't the player's to bind** (`Game.AddInputs`), and a control can't take F3 or F5–F11. **F-keys.** F toggles a free camera (Space and C for up and down, Shift for faster). F3 toggles the debug overlay (`Game.Debug.cs`): in trek the chunk, position, surface, speed, request, pace, camera, sounds, particles, rain and what a cut-scene waits for; in a battle its state, turns, field and combatants. F5 toggles the pace, F6 the sky's placement and F7 the UI screen's height. In a battle, F9 moves the radar between the log box and the screen's corner, and F10 routs the enemies and F11 fells the party, so that the next turn's change (Z) wins or loses it (`Battle.Rout`, `Collapse`).
- **Debug:** holding either thumbstick down (L3 or R3) raises the tick rate from 60 to 240 a second, as far as the machine keeps up (`Game.SetTickRate`). The pause menu stays at 60.
- **Debug: holding Cancel (B, Backspace) for two seconds in a battle wins it** on the next turn the player plays, as F10 and Z would (`Battle.ForceWin`, `Game.HoldToWin`). The seconds are the clock's, so fast-forward doesn't shorten them. Not in the Shadow's battles, which end in the merge or its vanishing, never a win.
- **Release builds have none of these** (`Game.Debugging`, `OS.IsDebugBuild()`, false in the release packages): the debug keys' actions exist with nothing bound to them, so `--press battle_rout` still works, the overlay starts hidden, fast-forward has no buttons and holding B doesn't win. A run under the Godot editor's binary is a debug build, with all of them and the overlay showing.

## The command line

After `--`: `tools/godot.ps1 --path src/AidynRenewed.Game -- --chunk I08 --at 16,62 --yaw 0 --pitch -15 --distance 5 --hold move_forward,4 --screenshot <absolute path>.png` starts somewhere, holds an input, saves the window and quits. The run gives up after a minute. `LaunchOptions` reads the options (on top of `CommandLine`, the parser and screenshot the editor shares), `Game.Start` builds the game in named steps from them, and `Game.Debug.cs` carries out the ones that drive it (`RunLaunchActions`). The launch options run once a run: a load or a game over that starts the scene again doesn't play them again.

- **Where:** `--set n`, `--chunk`, `--at x,z` (by default where a new game starts), `--yaw`, `--pitch`, `--distance`; `--fly x,y,z` starts with the free camera, which scene objects' distances are then measured from; `--camera outdoor|interior` starts in either mode (by default the start chooses as a door into its chunk would). Gwernia's open ground is around (30–80, 30–80) in M07, for example `--chunk M07 --at 40,55`; elsewhere in M07 there's no ground, and he falls and is lifted again and again, as in the original ([movement](movement.md)).
- **The game:** `--save <path>` starts from a save, where it stands unless `--chunk` or `--at` say otherwise. `--flags 5,50` sets plain flags before anything loads. A plain launch shows the title, its intro cards first, over a new game ([ui](ui.md#the-title-screen)), and its New Game plays the opening cinematic, then script 866 on its stage, then trek in I08 (`GameSession.StartNewGame`, [cinematics](cinematics.md#what-starts-them)). A save with no place starts as New Game does, without the title (`GameState.StartsAsNewGame`, [saves](saves.md#the-format)). Any option that says where to start or drives the run (`--save`, `--set`, `--chunk`, `--at`, `--flags`, `--fly`, `--hold`, `--press`, `--menu`, `--cutscene`, `--cinematic`, `--battle`, `--screenshot`) skips the title and the opening and starts in trek, where the opening's cut-scene still starts from its object unless `--flags 5,11` is added; `--opening on` or `off` says which outright, and `--opening on` plays it without the title. `--title cards` shows the title with its cards, `--title logo` without them, and `--title off` not at all; options are pairs, so `--title` takes one of those. `--time <hours>` sets the time of day.
- **Input:** `--hold` holds actions for so many seconds, several joined with `+`, as in `move_forward+walk,4`. `--press pause,menu_member_left,menu_right` presses actions in turn, a fifth of a second apart, as input events, which `--hold` doesn't make; the screenshot waits for them. The names are the controls' actions, read by the situation the game is in, so the menus take `menu_accept` and `menu_down`, a battle `battle_attack` and `target_left`, a conversation the menus' `menu_accept` and `menu_down` too, and trek `pause` and `use`. Among them, `wait:2` waits two seconds more; `battle_target:1.3` holds the action that long, pressed and let go as events, so combat's held menus hear both; and a `+` after it (`battle_spells:1.6+`) sends the next presses while it's held. A binding's name, `Key:P`, `Joy:Y` or `Axis:LeftX-`, presses that input itself, as the Controls page's prompt hears it. `battle_rout` routs a battle's enemies, as F10 does.
- **Menus and scenes:** `--menu 1` opens the pause menu, `--menu system`, `party` or `world` opens it on that tab, and `--menu loot` opens an empty loot window. `--cutscene aidyn:dialogue/0x0365` plays a cut-scene at once (the goblin ambush). `--battle aidyn:voxel/0x0F6B/3[,<arena>][,ambush]` starts a battle with that monster party where the player stands, in the arena given or the one the terrain chooses. `--radar box` puts the battle screen's radar in the log box (F9 swaps it). `--cinematic <n>` plays a cinematic, 0 to 3, without the menu after, and what follows it in the story (the opening's script, Roog's True Name, the ending's credits and the game's end); `--cinematic 0,5,300` starts at shot 5's time 300, and `--cinematic 0,5,300,hold` stands still there.
- **Weather:** `--weather rain|snow|fog|clear[,intensity[,fog]]` sets it at once, already set in and with the rain sky up (rain and snow default to 0.5 with fog 0.2 and a storm as hard as the rain; fog to 0.5). Rain and snow take a few seconds to fall into view from a standing start, so hold something harmless, such as `--hold walk,8`, before the screenshot.
- **Settings for the run:** `--ui-lines <n>`, `--sky original|projected`, `--pace`, `--draw-distance original|extended`, `--object-distance <scale>`, `--detail nearest`, `--surface-detail original|full`, `--blending original|smooth`, `--precipitation <scale>` (up to 8) and `--spell-auras each` lie over the player's settings for the run (`LaunchSettings`), and are never written to `settings.json`. Each holds until the player changes that setting, in the options menu or with F5, F6 or F7; `--pace` gives way to the Pace setting. `--lights off` lights bodies and actors by the sky alone ([rendering](rendering.md#point-lights)), and `--spell-fx off` drops spells' visuals, sky dimming and body tints ([combat](combat.md#what-spells-look-like)), as baselines.
- **Screenshots.** The path must be absolute, or Godot saves it relative to the project. `--ui-screenshot <png>` saves trek's UI screen with it, in its own pixels and with its alpha, for measuring the HUD and the battle screen against the user's captures. `--screenshot <png> --frames <n>` saves the next n frames as they're rendered, in real time, as `<png stem>-000.png` on, kept in memory until the last: for what only shows above 60 fps, between ticks. To see something tick by tick, Godot's movie writer saves every frame at a fixed 60 a second: `tools/godot.ps1 --path src/AidynRenewed.Game --write-movie <absolute dir>/f.png --quit-after <frames> -- --menu party`. It records at the project's window size, 1280 × 960; Godot's `--resolution` doesn't change it, and `--ui-lines 960` puts a window pixel to each of the UI screen's.
- **GUI runs need a timeout:** launch with a process you can kill, not blocking on it.
